# 保存とクラウド同期

## 仕組み

| 保存先 | いつ | 内容 |
|---|---|---|
| この端末（IndexedDB） | 自動（変更があれば 1 分ごと、なくても 5 分ごと、ページを離れる時）、「今すぐ保存」ボタン | 下のセーブデータ |
| ファイル（`.hakoniwa`） | 「ファイルに書き出す」「ファイルから読み込む」 | 同じセーブデータ。控えや別の端末への引っ越しに |
| Google Drive（アプリ専用フォルダ） | Google でログインしていれば自動（下の「Google 同期の動き」） | 同じセーブデータ。端末間の同期とバックアップに |

- セーブデータは「生成の設定（シード・サイズ・地形のパラメータ）＋地形の差分＋畑・植林・持ち物」を JSON にし、gzip で圧縮したもの。地形そのものは保存しない（シードから毎回同じものを作れるため）
- 形式にはバージョン番号（`SAVE_VERSION`）があり、形式を変えても古いデータを読めるようにする（`src/save/format.ts` の `migrate()`）
- 初めて保存する時に `navigator.storage.persist()` でブラウザに「消さないで」と頼む。断られた場合はメニューに表示されるので、書き出しで控えを取っておく
- 起動時、閉じていた間の時間（最大 7 日）を 15 分ずつ進める。その時々の季節・天気（雨なら畑が湿る）で育つ

## Google 同期の動き

- メニューの「💾 保存」で「Google でログイン」を押す（初回は同意画面）。以後、ログイン中のアカウントと最後に同期した時刻が出る
- **PC**：プレイヤーが手を加えていれば、5 分に 1 回まで Drive に送る。ページが隠れる・閉じる時にも送る
- **スマホ**：Drive の箱庭を読んで見るだけ。Drive へは書き込まず、ログイン中は編集もできない（ログアウトすれば今までどおり遊べる）
- **どちらを使うかの決め方**：保存時刻ではなく、端末ごとの「最後に同期した Drive の版」と「その後に手を加えたか」で決める
  - 別の PC で遊んだ後に古い PC を開いた：手を加えていなければ、黙って Drive の箱庭に追いつく
  - 両方で手を加えていた：どちらを残すか聞く（Drive を上書きする時はもう一度確認）
  - スマホで初めてログインした時、スマホに手を入れた箱庭があれば「Drive の箱庭に入れ替えますか？」と聞く
- アクセストークンは約 1 時間で切れ、タブを閉じると消える。開き直した時などは「タップして同期を続ける」を押す（多くは一瞬で閉じるポップアップで済む）。自分から何度もポップアップを出すことはしない
- アプリ専用フォルダはユーザーの Drive の一覧には出ず、他のファイルにも触れない
- ログアウトしても、この端末の箱庭はそのまま

## 公開先：Cloudflare Pages

- URL：`https://miniature-hakoniwa.pages.dev`
- リポジトリ：`mizki15/miniature-hakoniwa`（非公開）。`main` に push すると自動で公開される
- Pages の設定
  - フレームワーク：なし（Vite）
  - ビルドコマンド：`npm run build`
  - 出力ディレクトリ：`dist`
  - 環境変数：`VITE_GOOGLE_CLIENT_ID`（ビルドの時に埋め込まれる）、`NODE_VERSION` = `22`（vite が Node 20.19 以上 / 22.12 以上を求めるため）
- 以前のポートフォリオ（Render の legendary-pancake）の `/hakoniwa/` は、この URL へ転送する

## Google 同期を使えるようにする（開発者向け）

同期はサーバーを使わず、ブラウザから直接 Google の API を呼ぶ。そのために **OAuth クライアント ID** が必要。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を有効にする
3. 「OAuth 同意画面」を設定する
   - ユーザーの種類：外部
   - スコープに `.../auth/drive.appdata`（アプリ専用フォルダ）を追加
   - 公開前は「テストユーザー」に自分のアカウントを追加（テスト中は 100 人まで）
4. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」
   - 種類：ウェブ アプリケーション
   - 承認済みの JavaScript 生成元：`http://localhost:5173`（開発用）と `https://miniature-hakoniwa.pages.dev`
   - リダイレクト URI は不要（トークンモデルを使うため）
5. クライアント ID を 2 か所に入れる
   - 開発用：プロジェクト直下の `.env.local`（Git に入れない）に `VITE_GOOGLE_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com`
   - 公開用：Cloudflare Pages の環境変数 `VITE_GOOGLE_CLIENT_ID`（入れた後に再デプロイ）
6. `npm run dev` を起動し直す

### 注意

- クライアント ID は公開されても問題ない値（秘密の鍵ではない）。ただし生成元の URL で使える場所が制限される
- `npm run dev:lan`（`https://192.168.…`）は生成元に登録できないので、スマホでの確認は公開版（Pages）で行う
- 一般公開する時は OAuth 同意画面を「本番」にする必要がある（`drive.appdata` は審査の軽いスコープだが、プライバシーポリシーの URL などが必要）
