# 保存とクラウド同期

## 仕組み

| 保存先 | いつ | 内容 |
|---|---|---|
| この端末（IndexedDB） | 自動（変更があれば 1 分ごと、なくても 5 分ごと、ページを離れる時）、「💾 保存」ボタン | 下のセーブデータ |
| ファイル（`.hakoniwa`） | 「⬇ 書き出す」「⬆ 読み込む」 | 同じセーブデータ。控えや別の端末への引っ越しに |
| Google Drive（アプリ専用フォルダ） | 「☁ Google Drive」ボタン | 同じセーブデータ。端末間の同期に |

- セーブデータは「生成の設定（シード・サイズ・地形のパラメータ）＋地形の差分＋畑・植林・持ち物」を JSON にし、gzip で圧縮したもの。地形そのものは保存しない（シードから毎回同じものを作れるため）
- 形式にはバージョン番号（`SAVE_VERSION`）があり、形式を変えても古いデータを読めるようにする（`src/save/format.ts` の `migrate()`）
- 初めて保存する時に `navigator.storage.persist()` でブラウザに「消さないで」と頼む。断られた場合は右パネルに表示されるので、書き出しで控えを取っておく
- 起動時、閉じていた間の時間（最大 7 日）を 15 分ずつ進める。その時々の季節・天気（雨なら畑が湿る）で育つ

## Google Drive を使えるようにする（開発者向け）

Drive 連携はサーバーを使わず、ブラウザから直接 Google の API を呼ぶ。そのために **OAuth クライアント ID** が必要。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を有効にする
3. 「OAuth 同意画面」を設定する
   - ユーザーの種類：外部
   - スコープに `.../auth/drive.appdata`（アプリ専用フォルダ）を追加
   - 公開前は「テストユーザー」に自分のアカウントを追加（テスト中は 100 人まで）
4. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」
   - 種類：ウェブ アプリケーション
   - 承認済みの JavaScript 生成元：`http://localhost:5173`（開発用）と、公開先の URL（例：`https://〜.onrender.com`）
   - リダイレクト URI は不要（トークンモデルを使うため）
5. プロジェクト直下に `.env.local` を作り、クライアント ID を書く（このファイルは Git に入れない）

   ```
   VITE_GOOGLE_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com
   ```

6. `npm run dev` を起動し直す

### 動き

- 「☁ Google Drive」を押すとログイン（初回は同意画面）→ Drive のアプリ専用フォルダに `hakoniwa-save.bin` を置く
- Drive の方が新しい時（別の端末で遊んだ時など）は、読み込むか上書きするかを聞く
- アクセストークンは約 1 時間で切れる。切れていたら押した時に取り直す（多くは確認なしで取れる）
- アプリ専用フォルダはユーザーの Drive の一覧には出ず、他のファイルにも触れない

### 注意

- クライアント ID は公開されても問題ない値（秘密の鍵ではない）。ただし生成元の URL で使える場所が制限される
- 一般公開する時は OAuth 同意画面を「本番」にする必要がある（`drive.appdata` は審査の軽いスコープだが、プライバシーポリシーの URL などが必要）
