# Google アカウントでの同期と、Cloudflare Pages への引っ越し 設計書

- 日付：2026-11-21
- 状態：設計（実装前）
- 関係：[企画書](../../企画書.md)、[仕様書](../../仕様書.md)、[保存とクラウド同期](../../保存とクラウド同期.md)

## 0. 目的と方針

同じ Google アカウントでログインすれば、**PC で育てた箱庭の続きを別の PC でも遊べ、スマホでも眺められる**ようにする。ブラウザのデータが消えても、Google Drive に残っていれば戻せるようにする。

この先の目標として、**他の人に自分の箱庭を見せる・建物のデータを譲る**ことがある（以下「②」）。②は別のプロジェクトとして、これが終わってから設計する。今回はその土台として、ログインと公開先を整える。

### 目標

- Google アカウントでログインでき、ログイン中のアカウントと最後に同期した時刻が見える。ログアウトもできる
- PC では、遊んでいる間に Drive へ自動で保存する（ボタンを押さなくてよい）
- 起動した時に Drive の方が新しければ、それを読み込むか聞く（PC を 2 台使う場合のため）
- スマホでは、起動した時に Drive の最新の箱庭を表示する。**スマホは見るだけで、Drive へは書き込まない**
- 箱庭を Cloudflare Pages で公開し、そこで Google ログインが使える。GitHub に push すると自動で公開される

### 目標にしないこと（今回）

- ②（見せ合い・譲渡・共有リンク・一覧）。サーバー（Cloudflare Workers など）も今回は作らない
- スマホでの編集と、それに伴う競合の解決
- 複数の箱庭（セーブ枠）
- Google 以外のログイン

### やってはいけないこと（失敗とみなす）

- **Drive の古いデータで、新しい箱庭を黙って上書きする**こと（どちらの向きでも）。迷う時は必ず聞くか、何もしない
- スマホが Drive に書き込むこと
- ログインしていない人が、今までどおり遊べなくなること（端末内の保存とファイルの書き出し・読み込みはそのまま使える）
- 何もしていないのにログインのポップアップが何度も出ること
- アクセストークンを、タブを閉じた後まで残すこと

## 1. 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 公開先 | **Cloudflare Pages**（プロジェクト名 `miniature-hakoniwa`、URL `https://miniature-hakoniwa.pages.dev`）。browser_miniature を GitHub の `mizki15/miniature-hakoniwa`（公開）に上げ、Pages の GitHub 連携で push ごとに自動公開 | ②のサーバーを同じ場所（Workers）に置ける。手でのコピーが要らなくなる |
| 今の公開先（Render） | legendary-pancake の `/hakoniwa/` は Cloudflare 版へ**転送**し、`apps/hakoniwa/dist/` は消す。ポートフォリオのカードのリンクも差し替える（Claude の判断） | 古いリンクを切らないため。Google ログインは 1 か所（Pages の URL）でだけ使う |
| 保存先 | Drive の `appDataFolder`（スコープ `drive.appdata`）に `hakoniwa-save.bin` の 1 ファイル。今の `src/save/drive.ts` を使う | 既にある。ユーザーの他のファイルに触れず、審査も軽い |
| 一次保存 | 今までどおり端末内（IndexedDB）。Drive はバックアップ兼端末間の同期 | 企画書 4.4 の方針 |
| スマホ | ログイン中は見るだけ（道具を止める）。今の `isMobile` の判定（`main.ts`）を使う | ご本人の判断（競合と操作感） |

## 2. 動き

### 2.1 ログインと表示

メニューの「💾 保存」の欄に、Google の状態を出す。

```
ログイン前：  [Google でログイン]  端末間で同期・バックアップ
ログイン中：  ☁ name@gmail.com   同期 14:32 ✓   [ログアウト]
要再ログイン：☁ name@gmail.com   ⚠ 同期が止まっています  [再ログイン]
```

- 今の「Google Drive と同期」ボタンは、この表示に置き換える。手動で今すぐ同期するボタンは残してよい（Claude の判断。ビルダーに任せる）
- アカウント名は Drive API の `about?fields=user(emailAddress,displayName)` で取る（追加のスコープが要らない見込み。取れなければ `email` スコープを足す。ビルダーが確かめる）
- ログアウト：`google.accounts.oauth2.revoke` でトークンを取り消し、保存しているログインの印を消す。端末内の箱庭はそのまま

### 2.2 ログインの続け方（ページを開き直した時）

ブラウザだけで動くトークンモデルでは、リフレッシュトークンを持てない。アクセストークンは約 1 時間で切れ、ポップアップはユーザーの操作からしか確実に出せない。そこで次のようにする（Claude の判断）。

- 「前にログインした」という印と、メールアドレスを `localStorage` に残す（トークンそのものは残さない）
- アクセストークンは `sessionStorage` に有効期限つきで置く。同じタブで開き直しても、1 時間以内なら取り直さない。タブを閉じれば消える
- 起動した時に印があって有効なトークンがなければ、「☁ タップして同期を続ける」を目立つように出す。押すと `login_hint` 付きでトークンを取り直す（多くは一瞬で閉じるポップアップで済む）
- トークンが切れた時（401 か、期限が近い時）は自動同期を止めて「要再ログイン」の表示にする。自分からポップアップは出さない

> 毎回タップが要らない形（サーバーがリフレッシュトークンを持つ方式）は、②でサーバーを作る時にあらためて考える。

### 2.2b 「新しい」の決め方（同期の判断の芯）

保存時刻（`savedAt`）どうしの比べ合いでは決めない。開いただけの PC も自動保存で `savedAt` が「今」になり、古い箱庭が新しく見えてしまうため。代わりに次の 2 つで決める（Claude の判断）。

- **同期の印**：端末ごとに「最後に同期した時の Drive のファイルの版」（Drive の `version` か `modifiedTime`）を `localStorage` に残す。Drive の今の版がこれと違えば「Drive が変わった」
- **自分の変更**：前回の同期のあとに、**プレイヤーが手を加えたか**（畑・植林・建物・地形の編集。今の `game.unsaved` に当たるもの）。時間が進んだだけ（作物が育った、季節が変わった）は変更に数えない

| Drive が変わった | 自分が変えた | すること |
|---|---|---|
| いいえ | いいえ | 何もしない |
| いいえ | はい | Drive に送る |
| はい | いいえ | 黙って Drive の箱庭を読み込む（見ていただけなので失うものがない） |
| はい | はい | 聞く。両方の時刻を見せ、「Drive の箱庭を読み込む／この端末の箱庭で Drive を上書きする」の 2 択 |

- **初めて同期する端末**（同期の印がない）：Drive にデータがなければ送る。Drive にあって、端末内の箱庭にプレイヤーの手が入っていなければ（新しく作っただけなら）黙って読み込む。手が入っていれば聞く
- 迷う時（Drive の情報が取れない、印が壊れているなど）は何もしない

### 2.3 PC（遊ぶ端末）の自動同期

- 端末内に保存するたびに、**前回 Drive に送ってから 5 分以上たっていて、自分の変更があれば**（2.2b）Drive にも送る
- ページが隠れる時・閉じる時（`visibilitychange` の hidden、`pagehide`）にも、変更があれば送ろうとする。届かなくても、次に開いた時の比較で拾えるので構わない
- 送る前に Drive の版を確かめ、**同期の印と違えば送らずに 2.2b の表に従う**。別の PC で遊んだ後に、古い PC が上書きするのを防ぐ
- 失敗した時は右下に小さく出すだけで、遊ぶのは止めない。次の機会にまた送る

### 2.4 起動した時（PC）

1. 今までどおり端末内の箱庭を読み込んで表示する（ここでは待たない）
2. ログインしていれば（有効なトークンがあれば。なければ 2.2 のタップを待つ）Drive の情報を取る
3. 2.2b の表に従う。聞く時の文の例：
   - 「この端末と Google Drive の両方で箱庭が変わっています。Drive：11/21 14:32 ／ この端末：11/20 22:10」
   - Drive の箱庭を読み込む：Drive の箱庭にして端末内にも保存する
   - この端末の箱庭を残す：Drive を上書きする（確認の一言を添える）
4. タップを待っている間に自動保存が走っても、2.2b の判断には影響しない（保存時刻ではなく印と変更で決めるため）

### 2.5 スマホ（見る端末）

- 起動した時にログインしていれば Drive の最新を読み込んで表示する。端末内にも控えとして保存する（次に開いた時にすぐ出すため）
- **ログイン中のスマホは道具を止めて、見るだけにする**（ご本人の決定）。畑・植林・地形の編集・建物などの道具を出さず、カメラの操作と眺めることだけができる。ログアウトすれば今までどおり遊べる
- Drive へは一切書き込まない。手動の同期ボタンも「Drive から読み込む」だけにする
- **初めてログインした時、スマホにプレイヤーの手が入った箱庭があれば聞く**（ご本人の決定）：「Drive の箱庭に入れ替えますか？（今の箱庭は書き出しで控えを取れます）」。入れ替えない場合はログインを取りやめ、今のまま遊べる状態に戻す（Claude の判断）。手が入っていなければ黙って入れ替える
- アプリを前に戻した時（`visibilitychange` の visible）に Drive の版が変わっていれば、黙って読み込み直す（見るだけで失うものがないため。Claude の判断）

### 2.6 ログインしていない時

今までどおり。端末内の保存とファイルの書き出し・読み込みだけで遊べる。

## 3. 公開の準備

### 3.1 Cloudflare Pages

- browser_miniature を GitHub の `mizki15/miniature-hakoniwa`（新規・公開。ご本人が決定）に上げる
- Pages のビルド設定：コマンド `npm run build`、出力 `dist`、`base` は `/`（`build:portfolio` の `/hakoniwa/` は不要になる）
- `VITE_GOOGLE_CLIENT_ID` は Pages の環境変数に入れる（ビルドの時に埋め込まれる）
- 開発者ツール用の `window.__hakoniwa` は仕様書で「公開前に外す」となっている。今回、本番ビルドでは出さないようにするかはビルダーが判断する（デバッグパネルも同様）

### 3.2 Google Cloud（ご本人の作業）

[保存とクラウド同期](../../保存とクラウド同期.md) の手順どおり。承認済みの JavaScript 生成元に `http://localhost:5173` と `https://miniature-hakoniwa.pages.dev` を登録する。テスト中は、使うアカウントを「テストユーザー」に足す。

### 3.2b 誰が何をするか

- ご本人：Cloudflare のアカウントと Pages のプロジェクトを作り、GitHub と連携する（アカウントづくりと連携の許可はご本人の操作）。Google Cloud の設定（3.2）
- Claude：GitHub のリポジトリを作って push する（ご本人の了承を得てから）、Pages のビルド設定の値を用意する、コード一式
- 順番：コードは localhost で先に作って確かめる → Pages で公開 → その URL を Google に登録 → スマホで確かめる → legendary-pancake の転送（このプロジェクトの最後の段階として行う）

### 3.3 legendary-pancake（Render）

- `apps/hakoniwa/routes.py` を、`/hakoniwa` と `/hakoniwa/` を `https://miniature-hakoniwa.pages.dev` へ転送するだけにする。`dist/` は消す
- `portfolio/projects.py` の箱庭のカードのリンクを Pages の URL にする
- 別のリポジトリなので、変更は別のコミット（別の作業）になる

## 4. やり方の比較（検討した案）

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. Cloudflare Pages に移す（採用）** | 箱庭を Pages で公開、Render からは転送 | 自動公開。②のサーバーを Workers で同じ場所に置ける。無料枠が広い | URL が変わる。GitHub に上げる作業が要る |
| B. 今の Render のまま | Render の URL を Google に登録 | 新しい設定がほぼない | ②を作る時、無料の Web サービスは眠る（起動に数十秒）うえ、ファイルが再起動で消える |
| C. 両方に置く | Render 版も残す | 古い URL もそのまま | ログインが URL ごとに分かれ、同期は片方でしか使いにくい |

同期のやり方では、サーバーを置いてリフレッシュトークンを持たせる案も考えた。毎回のタップが要らなくなるが、今回はサーバーを作らない方針なので、②の時に回す。

- `window.__hakoniwa` とデバッグパネルを本番で隠すかどうか
- 文書（仕様書・保存とクラウド同期.md）の更新
