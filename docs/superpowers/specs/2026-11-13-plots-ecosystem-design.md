# 区画の拡張・生態系・解放 設計書

- 日付：2026-11-13
- 状態：設計（実装前）
- 関係：[仕様書](../../仕様書.md)（現在の実装）

## 0. 目的と方針

眺めて和む箱庭に、「毎日開きたくなる理由」と「少しずつ育っていく実感」を足す。

- **環境を整えると生き物が来る**。来た生き物を見つけて図鑑を埋める。
- **見つけると発見ポイントが入り、土地（区画）や新しいもの（ブロック・作物など）が開く**。
- 進捗の制度が「急かす」ものにならないようにする。期限・ノルマ・失うものは作らない。今ある道具・ブロック・作物は最初から全部使える。
- 区画をすべて開いても重くならないこと。目標は「16 区画すべてを開いても、今の 128×128 の箱庭と同じくらいの負荷」。

### 決めたこと

| 項目 | 決定 |
|---|---|
| 区画の大きさ | 64×64。最初は 1 区画、最大で 4×4 = 16 区画（256×256） |
| 広げ方 | 「土地の権利」を使い、隣の空いた区画を自分で選んで開く |
| 解放の条件 | 図鑑が中心で、農業も少し絡める |
| 図鑑への登録 | 来たら「見かけた」、カーソルを合わせると「観察した」の 2 段階。ポイントは観察した時に入る |
| 古いセーブ（v1） | 引き継がない。「古い形式です」と伝えて新しく始める |
| 作り方 | 256 の枠を最初から確保し、解放した区画だけ作って描く（下の A 案） |

### 検討した作り方

- **A（採用）**：256×256 の枠を常に確保し、開いた区画だけを生成・メッシュ化・描画する。ボクセルの番号や 3D テクスチャが変わらないので、色の馴染ませ・編集・当たり判定をそのまま使える。メモリはボクセル 4 MB、3D テクスチャ 4 MB。
- B：区画ごとに別のデータを持つ。メモリは最小だが、色の馴染ませ・編集・当たり判定がすべて区画をまたぐ処理になり複雑。
- C：256 を全部作ってから隠す。簡単だが、起動の重さが常に最大のままになる。

## 1. 枠と区画

### 1.1 座標とデータ

- 枠の大きさ `FRAME = 256`、区画の大きさ `PLOT = 64`、区画の数は `4×4`。1 区画はチャンク（32）の 2×2。
- 高さの上限は今のまま 64（`WORLD_HEIGHT`）。
- ボクセルの番号は `x + z*FRAME + y*FRAME*FRAME` で固定する。セーブの差分（`edits`）もこの番号で持つ。
- 区画の番号は `px + pz*4`（`px, pz` は 0〜3）。開いた区画は 16 ビットのマスクで持つ。
- **最初の区画は (1,1)**。4 方向どこへでも広げられる位置にする。
- `World` に `plots: number`（開いた区画のマスク）を足す。`size` は「枠の大きさ（256）」の意味になる。まだ開いていない区画のボクセルは空気（0）で、歩けない。

### 1.2 地形の生成を「枠の座標」で決まる形にする

区画を後から作っても、最初から全部作った時と同じ結果になるようにする。

- 高さ・地表の種類のノイズは今も絶対座標なので、そのまま使う。
- **川**：中心や幅が今はフィールドの大きさ `N` で決まっている（`terrain.ts` の 77〜79 行目）。これを `FRAME` 基準の固定値に変える。
- **木と花**：今は順番に乱数を引いて置いている（`rand()`）。これを「座標とシード値から決まるハッシュ乱数」に変える。
  - 木どうしの間隔（5×5 の範囲に他の木がない）は、順番に依存しない形にする。たとえば「格子の中で、ハッシュ値がいちばん大きい列だけに木を置ける」ようにする。
- 生成する関数の形を `generatePlot(world, px, pz, seed, params)` にする。指定した区画の 64×64 列だけを書き込む。
  - 色の馴染ませやメッシュには、まわり 1 ボクセルの情報が要る。まだ開いていない隣の区画は空気のままでよい（外側の面は地層の断面として描く）。
- `applyEdits` は区画を作った後に、その区画に入る差分だけを当てる。

### 1.3 区画を開く流れ

1. エディタモードで、開いた区画に接していて、まだ開いていない区画を、半透明の枠（線と薄い面）で表示する。
2. 権利が 1 つ以上ある時にクリックすると、確認なしで開く。取り消しはできない。
3. ワーカーがその区画を生成し、次のチャンクのメッシュを作る。
   - 新しい区画のチャンク 4 つ
   - 境目に接する、隣の開いた区画のチャンク（今まで外側だった面が消えるため）
4. メインスレッドでは、新しいチャンクを足し、境目のチャンクを差し替える。あわせて、3D テクスチャのその範囲・木と花の配置・台座・動物が歩ける範囲を更新する。
5. 画面の止まりは 1 フレーム分の差し替えだけにする。生成とメッシュ化はワーカーで行う。

### 1.4 見た目

- 開いた区画の外側の面には、地層の断面がそのまま出る（まだの区画は空気なので）。
- 台座（今は 1 枚の箱）は区画ごとの板にする。いびつな形でも箱庭らしく見えるように、少しはみ出す縁を付ける。
- カメラの注目点・可動範囲・霧の距離・鳥の飛ぶ範囲・雨と雪の範囲は、「開いた区画を囲む四角」に合わせる。
- 区画を開いた時は、新しい区画が下から少しせり上がるような短い演出を入れる（0.6 秒程度）。

### 1.5 重くしないための工夫

| 対象 | 今 | 変更 |
|---|---|---|
| 影 | 箱庭全体を 1 枚の影の範囲で覆う | 注目点のまわり、カメラとの距離に応じた範囲だけを覆う（最小 48、最大 160 ボクセル）。広くなっても影が粗くならない |
| 地形のチャンク | 全部描く | チャンクごとに境界球を持たせ、画面外は描かない（three.js の frustum culling を効かせる） |
| 木・花 | 種類ごとに 1 つの InstancedMesh | 区画ごと・種類ごとに分け、画面外の区画は描かない |
| 遠くの木・花 | 近くと同じモデル | 注目点から遠い区画は、細かさ 1/1 の軽いモデルに切り替える（区画単位で切り替え） |
| 動物・鳥・雨粒・ホタル | 箱庭の大きさに比例 | 開いた面積に応じて増やすが、上限を設ける（動物 24、訪問者 8、鳥・雨粒は今の 128 と同じ数まで） |
| 3D テクスチャ | 作り直す | 区画を開いた時に、その範囲だけを書き換えてアップロードする |

- 確かめ方：`__hakoniwa.bench` で、1 区画・4 区画・16 区画を、高・中・低画質の 1280×720 で測る。16 区画が今の 128（4 区画相当）の 1.3 倍以内に収まることを目標にする。

### 1.6 デバッグ

- デバッグウィンドウの「大きさ」の選択をなくす。
- 代わりに「権利 +1」「全区画を開く」を置く。

## 2. 生態系

### 2.1 生き物の 2 種類

- **住人**：今の 7 種（うさぎ・たぬき・きつね・しか・あひる・りす・はりねずみ）。条件がそろうと引っ越してきて、そのまま住む（保存する）。
- **訪問者**：しばらく滞在して去る。滞在は現実の時間で 20〜60 分。保存はせず、箱庭を開いている間だけ来る。閉じていた間に来たものはいなかったことにする。

### 2.2 住人が引っ越してくる条件

| 住人 | 条件 |
|---|---|
| うさぎ | 最初からいる（1〜2 匹） |
| りす | 木 15 本以上 |
| あひる | 水辺（水に接する歩ける列）20 以上 |
| しか | 草地 1500 列以上 |
| たぬき | 木 30 本以上 |
| きつね | 草地 2500 列以上 |
| はりねずみ | 畑か花 30 以上 |

- 判定は 2.4 の抽選と同じ時に行う。条件を満たした種類が、1 回の判定で 1 匹まで引っ越してくる。
- 住人の上限は「開いた区画の数 × 3」（最大 24）。同じ種類は最大 4 匹。

### 2.3 訪問者（最初の 12 種）

| 訪問者 | 必要な環境 | 季節・時間・天気 | 珍しさ | 現れる場所 |
|---|---|---|---|---|
| チョウ | 花 20 以上 | 春・夏、昼、雨以外 | ふつう | 花の上を飛ぶ |
| ミツバチ | 花 40 以上＋作物 1 以上 | 春・夏、昼、雨以外 | ふつう | 花と作物の間を飛ぶ |
| スズメ | 畑 1 以上 | 一年中、昼 | ふつう | 畑のまわりを跳ねる |
| カエル | 水辺 10 以上 | 春・夏。雨だと来やすい（2 倍） | ふつう | 水辺 |
| 魚の影 | 深さ 3 以上の水 30 マス以上 | 一年中 | ふつう | 水の中（水面下の影） |
| トンボ | 水辺 10 以上 | 秋、昼 | ややまれ | 水辺の上 |
| キツツキ | 木 30 本以上 | 一年中、昼 | ややまれ | 木の幹 |
| ホタル | 水辺 10 以上＋草地 | 初夏（夏の前半）、夜 | ややまれ | 今のホタルの光を図鑑の対象にする |
| カタツムリ | 花か畑 10 以上 | 雨の夜だけ | ややまれ | 花・畑のそば |
| シマエナガ | 木 20 本以上 | 冬、昼 | まれ | 木の枝 |
| フクロウ | 木 60 本以上 | 夜 | まれ | 木の上 |
| カワセミ | 魚の影がいる時の水辺 | 一年中、朝（5〜9 時） | まれ | 水辺の上 |

- 「昼」「夜」「朝」は、今の昼夜（現実の時刻）で決める。季節・天気は今の暦と天気を使う。デバッグの季節・天気の上書きも効く。
- 見た目はローポリの小さなモデル（仮）。動きは種類ごとに単純なもの（飛ぶ・跳ねる・止まる・泳ぐ）にする。

### 2.4 来るかどうかの判定

- 箱庭内の時計で約 5 分ごとに判定する。
- 条件を満たす種類ごとに抽選する。確率の目安は、ふつう 40%、ややまれ 15%、まれ 5%。すでに来ている種類は抽選しない。
- 同時にいる訪問者は最大 8 匹。
- 現れる場所は、条件に合う列からランダムに選ぶ（開いた区画の中だけ）。
- 環境の数（花・木・草地・水辺・深い水・畑・作物）は、地形を変えた時・区画を開いた時・作物が増減した時にだけ数え直す。毎フレームは数えない。

### 2.5 図鑑の 3 段階

| 段階 | どうなると | 図鑑の表示 |
|---|---|---|
| ？？？ | まだ来ていない | ヒントだけ（例：「花がたくさん咲く所に来るらしい」） |
| 見かけた | 箱庭に来た（住人が引っ越してきた時も含む） | シルエットと名前の一部 |
| 観察した | その生き物にカーソルを 1.5 秒合わせる | 名前・説明・好きな環境・観察した季節。発見ポイントが入る |

- 初めて来た時は「何かの気配がする…」とだけ小さく通知する。どこにいるかは教えない。
- 観察中は、ホバー表示に小さな進み具合の輪を出す。観察が済んだら「〇〇を観察した！ +2」と通知する。
- 図鑑には住人 7 種＋訪問者 12 種を並べる。
- 右パネルに「環境」の欄を足し、花・木・水辺・深い水・畑の数を出す。誰が来そうかの手がかりにする。

## 3. 解放

### 3.1 発見ポイント

| きっかけ | ポイント |
|---|---|
| 生き物を初めて観察する | ふつう 1・ややまれ 2・まれ 4（住人 7 種は「ふつう」扱い） |
| 訪問者を、その季節で初めて観察する（2 季節目以降） | 1 ずつ |
| 作物を種類ごとに初めて収穫する | 1 ずつ |
| 苗木が初めて木に育つ | 1 |

- 初めての観察で入るポイントの合計：住人 7 ＋ 訪問者 25 ＝ 32。
- 全部で手に入るポイント：初めての観察 32、季節ごとの観察 18（一年中来る 5 種 × 3 季節、春夏の 3 種 × 1 季節）、初めての収穫 4（ひまわりを含む）、苗木 1。合計 55 で、全区画に要る 45 を上回る。季節がひと巡りしないと全部は開かない。
- 生き物の種類を増やせば、ポイントの入り方も自然に増える。

### 3.2 土地の権利

- 発見ポイントの累計が 3 の倍数になるごとに、権利が 1 つ増える。15 個（45 ポイント）で 16 区画すべてが開く。
- 権利は貯めておける。使う時はエディタモードで隣の区画をクリックする。
- 残りの権利と、次の権利までのポイントを右パネルに出す。

### 3.3 生き物などに結びつけて開くもの

| きっかけ | 開くもの | 種類 | 内容 |
|---|---|---|---|
| チョウを観察 | 花の種 | 道具 | エディタの道具「花を植える」。草地に花を 1 つ植える |
| キツツキを観察 | 丸太 | ブロック | 「ブロックを置く」で選べる |
| 魚の影を観察 | 砂利 | ブロック | 同上 |
| カエルを観察 | 睡蓮 | 小物 | 水面に置ける |
| フクロウを観察 | 灯籠 | ブロック | 夜に光る。ホタルの光の仕組みを使い、灯籠とホタルを合わせて最大 32 個まで |
| カボチャを初めて収穫 | ひまわり | 作物 | 夏が旬。育つのに 6 時間。花として数えるので、ミツバチが来やすくなる |

- 「土を盛る」の道具を「ブロックを置く」に広げ、土に加えて、解放したブロックを選べるようにする。
- 解放した時は通知を出し、エディタの該当する道具やブロックに「新」の印を付ける。一度選ぶと印は消える。

## 4. 保存

`SAVE_VERSION` を 2 にする。v1 のデータを読もうとした時は「古い形式のため新しく始めます」と伝えて、新しい箱庭を作る（v1 の差分は使えない）。

v2 で足すもの：

```ts
world: { seed, height, detail, flowerStyle, params }  // size は無くす（枠は固定）
plots: number                                        // 開いた区画のマスク
progress: {
  points: number                                     // 発見ポイントの累計
  rightsUsed: number                                 // 使った権利の数（権利の残り = floor(points/3) - rightsUsed）
  unlocks: string[]                                  // 'flowerSeed' | 'log' | 'gravel' | 'lily' | 'lantern' | 'sunflower'
  firsts: string[]                                   // 'harvest:turnip' など、初めての実績
  newMarks: string[]                                 // まだ選んでいない「新」の印
}
dex: Record<string, { seenAt: number; observedAt?: number; seasons: number[] }>
residents: [species, x, z, name][]
farm: { ... }                                        // 今のまま。col は枠の座標の列番号
```

- 訪問者は保存しない。
- 閉じていた間の成長（最大 7 日）は今のまま。住人の引っ越しも、閉じていた間は起きない。

## 5. 作る順番

一度に全部は作らない。それぞれの段階で動きと重さを確かめ、コミットしてから次へ進む。

1. **枠と区画**（1 章）
   - 地形の生成を枠の座標で決まる形にする
   - 区画ごとの生成と、境目のメッシュの作り直し
   - 開ける区画の枠の表示、権利、台座、カメラなどの範囲
   - 重さの対策
   - デバッグの「権利 +1」「全区画を開く」
   - 保存 v2（区画のマスクと権利まで）
2. **生態系**（2 章）
   - 環境の数え方
   - 住人の引っ越し
   - 訪問者 12 種と、来るかどうかの判定
   - 図鑑の 3 段階と観察
   - 右パネルの「環境」
3. **解放**（3 章）
   - 発見ポイントと権利のつながり
   - 6 つの解放（花を植える・丸太・砂利・睡蓮・灯籠・ひまわり）
   - 「新」の印、保存 v2 の残り

## 6. 今回入れないもの

- 全世界で同時に起きる出来事（流星群・満月など）
- 留守中に来た生き物の記録
- 共有リンク・写真モード・窓モード
- 収穫物を使うこと（エサ・巣箱など）
- 課金
