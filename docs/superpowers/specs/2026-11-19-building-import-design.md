# 建物の読み込み 設計書

- 日付：2026-11-19
- 状態：設計（実装前）
- 関係：[企画書](../../企画書.md)、[仕様書](../../仕様書.md)（現在の実装）

## 0. 目的と方針

プレイヤーが**自分のアイデアで建物を作り、箱庭に飾れる**ようにする。作り方は 2 通り。

- **AI に作らせる**：ゲームが用意した「AI に渡す説明文（規格）」に自分のアイデアを書き足し、ChatGPT や Claude などに渡す。返ってきた JSON をゲームに読み込む。
- **手で作る**：Blockbench（無料のモデリングツール）で作り、書き出した JSON を読み込む。AI が作ったものを Blockbench で開いて直すこともできる。

いずれは**作った建物を他の人と見せ合う**ことが目標。今回は見せ合う機能そのものは作らないが、規格はそれを前提に決める。

### 目標

- 規格どおりの JSON なら、誰が作っても箱庭の画風（フラットシェーディング・決まった色）で表示される。
- 規格に合わないものは読み込まず、**何がどう悪いかを日本語で具体的に伝える**。その文をそのまま AI に渡せば直してもらえるくらい具体的にする。
- 1 棟のデータが小さく（目安 数 KB、上限 64 KB）、テキストとして受け渡しできる。

### 目標にしないこと（今回）

- 見せ合い・共有の機能（URL 共有、一覧、評価など）
- 建物に住人が住む・出入りする・夜に窓が灯るなどの「暮らし」の機能。建物は**飾って眺めるもの**で、住むための建物でなくてよい
- テクスチャ（画像）による見た目。色はパレットだけ
- 自由な多角形（メッシュ）や、直方体以外の形
- スマホでの読み込み（スマホは閲覧限定の方針どおり、表示だけする）

### やってはいけないこと（失敗とみなす）

- 読み込んだデータの中の何かが**実行される**こと。データは数値と名前として読むだけ
- 壊れたデータや極端に大きいデータで、箱庭が落ちたり極端に重くなったりすること（将来は他人のデータを読むため）
- 読み込んだ建物だけ画風が浮くこと

### 決めたこと

| 項目 | 決定 |
|---|---|
| 形式 | **Blockbench の Bedrock 形式（`.geo.json`、Bedrock のジオメトリ JSON）** |
| 形 | 直方体だけ。回転は 3 軸とも自由な角度。大きさの制限は Minecraft のものではなく、この箱庭で決める（§2.4） |
| 色 | **グループ（ボーン）の名前でパレットの色を決める**（§2.3）。テクスチャと UV は無視する |
| 用途 | 飾り。住人や生き物の暮らしとは関わらない |

### 検討した作り方

- **A：glTF の一部だけを許す規格**。標準の形式で、Blender の出力も使える。しかし AI は長い base64 を書き損じやすい（2026-11-18 の実験で、Claude の出力は末尾 108 バイトが欠けて読めなかった。ChatGPT の出力は合格した）。データが大きく、人が読んで直せない。→ 不採用
- **B：部品を並べる独自 JSON**。AI が書きやすく、小さく、安全。ただし独自の形式で、エディタがない。→ 考え方は採用し、形式は既存のものに乗る（D）
- **C：細かいボクセル**。AI は大きな立体の格子を正しく書けない。企画書の「家・小物はローポリ」とも合わない。→ 不採用
- **D：Blockbench の形式に乗る（採用）**。B の良さ（直方体を並べるだけ、小さい、読める）に加えて、画面で作れるエディタがあり、AI もこの形式の例をたくさん知っている。
  - Java 版ブロックモデルの形式は、回転が 1 軸・22.5° 刻み、大きさが一辺 3 ブロックまでと縛りが強い。
  - **Bedrock 形式なら角度と大きさが自由で、しかも独自の方言にならない**ので、こちらを選んだ。
  - Bedrock 形式は面ごとに色の名前を付けにくいので、グループの名前で色を決める決まりだけを足す（Blockbench では名前を付けるだけなので、行き来は崩れない）。

## 1. プレイヤーから見た流れ

1. 「建物」の道具を開き、「AI に頼む」を押すと**説明文（規格＋パレット）がコピーされる**。プレイヤーは「作ってほしいもの」の欄に自分のアイデアを書き足して AI に渡す。
2. AI の返した JSON を**貼り付ける**か、`.geo.json` ファイルを**画面に落とす**。
3. 検査に通れば、建物の一覧（自分の建物の棚）に加わる。通らなければ、問題の一覧を表示する。一覧には「AI に直してもらう文をコピー」ボタンを付ける。
4. 棚から選び、地面の上に置く。向きは 90° 刻みで回せる。置いた建物は取り除ける。

## 2. 規格

### 2.1 読む部分

Bedrock のジオメトリ JSON のうち、次の部分だけを読む。それ以外は無視する（エラーにはしない）。

```
{
  "format_version": "1.12.0",            // 1.12.0 以降を受け付ける
  "minecraft:geometry": [ {                // 最初の 1 つだけ使う
    "description": { "identifier": "geometry.akai_yane_no_koya", ... },  // 名前として使う
    "bones": [
      { "name": "wall", "parent": "...", "pivot": [x,y,z], "rotation": [x,y,z],
        "cubes": [ { "origin": [x,y,z], "size": [w,h,d],
                     "pivot": [x,y,z], "rotation": [x,y,z], "inflate": n } ] }
    ]
  } ]
}
```

- 無視するもの：`uv`、`mirror`、`texture_width`/`texture_height`、`visible_bounds_*`、`locators`、`bind_pose_rotation` など
- **受け付けないもの**：`poly_mesh`（自由な多角形）。あればエラー（§0 の「目標にしないこと」）
- `inflate` は、直方体を各方向にその分だけ膨らませる値として扱う（Blockbench と同じ）

### 2.2 単位と向き

- **16 単位 = ボクセル 1 個**（Minecraft と同じ。この箱庭ではボクセル 1 個がおよそ 1 m）
- Y が上。底面は y = 0。建物の中心は x = 0, z = 0 付近に置く（Blockbench の初期の位置と同じ）
- 正面の向き：Blockbench で見た「北（North）」の面を正面とする。置くときの向きの基準になる（下の §5 で確かめる）
- 回転は度。回転の順番と、各軸の符号は Blockbench での見た目と一致させる（§5）

### 2.3 色（グループの名前）

- グループ（ボーン）の**名前がパレットの色の名前**になっている場合、その中の直方体をその色で塗る。
- 名前がパレットにないグループは、**親のグループの色**を受け継ぐ。
  - 用途で名前を付けたいときは、`roof` の中に `roof_left` を作る、のように入れ子にすればよい。
  - 名前の末尾に `_数字` や `_英字` を付けたもの（`roof_2`、`wall_front`）も、先頭がパレットの名前なら、その色とみなす。
- **どこまで親をたどっても色が決まらない直方体があれば、エラーにする**。どのグループかを名前で示す。

最初のパレット（私の案。テストしながら増減する）：

| 名前 | 色 | 用途の例 |
|---|---|---|
| `wall` | #A07A4E | 木の壁 |
| `wood` | #6E4C2E | 柱・扉・濃い木 |
| `plank` | #C8A070 | 明るい木 |
| `roof` | #C8403C | 赤い屋根 |
| `roof_blue` | #4A6A9A | 青い屋根 |
| `thatch` | #C9A85A | かやぶき・わら |
| `stone` | #9298A0 | 石・土台 |
| `brick` | #A85A44 | れんが |
| `white` | #F6F2EA | しっくい・窓・白 |
| `glass` | #BFD8E0 | ガラス |
| `dark` | #3A3A40 | 鉄・影 |
| `leaf` | #4F9A3C | 植え込み・つた |
| `flower` | #F2C94C | 花・飾り |

- `roof_blue` は「`roof` の後ろに `_blue` が付いたもの」ではなく、それ自体がパレットの名前。名前は長いものから順に照らし合わせる。
- 色の値は、他のモデル（作物・花）と同じく sRGB の 16 進で持ち、表示するときにリニアに直す。

### 2.4 上限（検査）

| 項目 | 上限 | 理由 |
|---|---|---|
| ファイルの大きさ | 64 KB | 共有を見すえて小さく保つ |
| 直方体の数 | 512 | 1 棟 6,144 三角形まで。箱庭全体の負荷を抑える |
| グループの数 | 128 | |
| グループの入れ子の深さ | 16 | |
| 外形（回転後） | 幅・奥行 各 8 ボクセル（128 単位）、高さ 12 ボクセル（192 単位） | 1 区画（64×64）に対して小さく保つ |
| 底面 | 一番低い点が y = 0（±0.5 単位まで許す） | 地面に置くため |
| 数値 | すべて有限の数（NaN・無限大でない） | |
| 大きさ `size` | 各成分が 0 以上。すべて 0 の直方体は捨てる | |

上限の数字は私の案で、作ってみてから調整する。

### 2.5 エラーの伝え方

- 問題をすべて集めてから一覧で出す（最初の 1 つで止めない）。
- 1 件ごとに「どこが」「どう悪いか」「どう直すか」を書く。例：「グループ `door` の色が決まりません。`wood` などパレットの名前を付けるか、色のあるグループの中に入れてください」
- 「AI に直してもらう文をコピー」で、元の依頼の続きとして渡せる文（問題の一覧＋「この点だけを直して JSON 全体を出し直してください」）をコピーする。

## 3. 作り（実装の方針）

### 3.1 ファイルの分け方（案）

- `src/build/geoParse.ts`：JSON → 検査済みの建物データ（`BuildingDesign`）。three.js に頼らない純粋な関数にし、テストから直接呼べるようにする（`world/plotBuild.ts` と同じ考え方）
- `src/build/geoMesh.ts`：`BuildingDesign` → メッシュ。直方体 1 個につき 12 三角形、面ごとに頂点を分けたフラットシェーディング。色は頂点カラー（`creatures/flowers.ts` の `colored` と同じ扱いで、`ao` 属性も付ける）
- `src/build/aiPrompt.ts`：AI に渡す説明文を作る（パレットと上限は、検査と同じ定数から書き出す。説明文と検査がずれないようにするため）
- 道具・置く操作は `game/controller.ts` と `game/picking.ts` の既存の仕組みに足す

### 3.2 建物データ（正規化した形）

読み込んだ JSON をそのまま持たず、検査を通った**必要な値だけの形**にして保存する。

```ts
interface BuildingDesign {
  id: string;          // 正規化したデータのハッシュ。同じ建物を 2 回読んでも 1 つにする
  name: string;        // identifier から。なければ「名前のない建物」
  cubes: [x0, y0, z0, x1, y1, z1, rx, ry, rz, px, py, pz, color][]; // 単位は 16 = 1 ボクセル、回転は親の分も合成済み、の形にするかは作る人が決める
}
```

- 親のグループの回転を直方体ごとに合成して持つか、グループの木のまま持つかは、作る人が決めてよい。どちらにしても §5 の見た目の一致が条件
- 元の JSON は保存しない（容量のため）。Blockbench で開き直したい人は、自分の手元のファイルを使う

### 3.3 保存

- セーブデータの版を上げ（`SAVE_VERSION` 3）、次を足す：
  - `buildings.designs`：`BuildingDesign[]`（棚）
  - `buildings.placed`：`[designId, x, z, rot][]`（`x, z` は枠のボクセル座標、`rot` は 0〜3 で 90° 刻み）
- v2 のデータは、空の棚として読む（`migrate()`）

### 3.4 置き方と表示

- 置ける場所：開いた区画の地面の上。建物の底面を、置いた位置の地面の高さに合わせる
- **住人・生き物との関係**：建物は飾りなので、生き物の動きの計算には加えない（めり込みは今回は許す）。めり込みが目立つようなら、建物の足元のマスに地上の生き物を出さない程度の対策を後で考える
- 同じ建物を複数置いたら、インスタンス描画にする
- 影・昼夜の明るさ・自動画質は、他のモデルと同じ材質を使って揃える
- スマホでは表示だけする（棚・置く操作は出さない）

## 4. テスト

- `geoParse` の単体テスト：
  - 規格どおりの最小の例が通る
  - 次のそれぞれがエラーになり、文に該当する名前が入る：色が決まらないグループ、`poly_mesh`、上限超え（数・外形・底面）、NaN、JSON として壊れている
  - 無視する項目（`uv` など）があっても通る
  - 同じ建物は同じ `id` になる
- 検査と AI 用の説明文が同じ定数から作られていることのテスト（説明文にパレットの全色・上限の値が含まれる）
- セーブデータ v2 → v3 の移行のテスト

## 5. 作り始める前に確かめること

この設計の一部は、資料を読んだだけで、まだ実物で確かめていない。最初の作業として、Blockbench（Web 版でよい）で次を確かめ、結果をこの設計書に書き足す。

1. 「Bedrock Entity」（または「Bedrock Model」）形式で、左右・前後で形が違う建物（例：正面にだけ扉、右側にだけ煙突）を作って書き出す。
   ゲームで読み込んで、**Blockbench で見た向きと同じになる**ことを確かめる。Bedrock 形式では X の向きが反転すると言われているので、特に左右を見る。
2. 直方体とグループに、3 軸すべての回転を付けて書き出す。回転の順番と符号が合うことを確かめる。
3. 書き出した JSON のフィールド名（`origin`・`size`・`pivot`・`rotation`・`inflate`・`parent`）と、`format_version` の値を記録する。
4. 入れ子のグループで、子の `pivot` が絶対座標か相対座標かを確かめる。

あわせて、AI に渡す説明文で ChatGPT と Claude（無料版）に 2〜3 棟作らせ、検査の合格率とエラーの文の分かりやすさを見る。
