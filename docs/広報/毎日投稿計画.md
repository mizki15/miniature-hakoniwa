## 基本ルール

- 毎回「**開発◯日目の振り返り**」と書く（過去の画面だと正直に書く。後で日付がずれていると突っ込まれない）。
- 1 本につき **画像 1〜4 枚か 10〜30 秒の GIF・動画** を 1 つ。隅に `@MiniHakoniwa` を小さく入れる。
- 決まったハッシュタグ：`#CubicHamlet #indiedev #gamedev #個人開発`（タグは 3〜4 個まで）
- 投稿は夜 20〜22 時ごろが反応をもらいやすい。予約投稿でまとめて仕込んでおくと楽。
- **出さないもの**：仕様書・設計書の中身、AI に渡す説明文の全文、同期の仕組み、公開ビルドの URL（アドレスバーを写さない）。

## 過去のバージョンの撮り方

1. 今の作業フォルダとは別の場所に、そのコミットの作業ツリーを作る：
   `git worktree add <別のフォルダ> <コミット>`
2. `node_modules` は今のフォルダのものへのリンクで済ませる（古いコミットで依存が違えば `npm install`）。
3. **ポートを今の開発用（5173）と変えて** 起動する。ポートが違えばブラウザの保存領域も別になるので、古い版が今のセーブデータを上書きしない。
4. 画面を撮る。撮り終えたら、先に `node_modules` のリンクを `rmdir` で外してから `git worktree remove <別のフォルダ>`（リンクを付けたまま消すと、本体の `node_modules` まで消えるおそれがある）。

撮影の道具は `docs/広報/撮影ツール/` にある。
- `chrome.exe --remote-debugging-port=9333 --user-data-dir=<使い捨てのフォルダ>` で撮影用の Chrome を別に開いておく。
- `cdp.mjs`：`nav <URL>`・`eval <JS>`・`shot <ファイル>`・`drag x1 y1 x2 y2 [right]`（右ドラッグで平行移動）・`wheel x y 量 回数`・`record 秒 <フォルダ>`（30fps のコマに書き出す）。
- `setup.js`：時刻・天気を決めて、左右のパネルを隠す（`window.__T`・`window.__W` で指定）。
- `wm.sh`：画像かコマのフォルダに `@MiniHakoniwa` を入れて png／mp4 にする。

- 録画の前に `node cdp.mjs hold` を裏で動かしておく（1920×1080 を保つ。これがないと録画の途中で画面の高さが変わる）。崩れたコマは `fixframes.sh <フォルダ>` で直せる。
- `click x y …`・`move x y`・`key <キー>`、`clear <origin>`（その版のセーブを消す）、`navwith <js> <URL>`（ページより先に JS を入れて開く。`timeshift.js` で時計を 8 時間進めるとオフライン進行を撮れる）。
- `setup2.js`：`setup.js` に季節（`window.__S`）と隠すパネル（`window.__HIDE`）を足したもの。
- `hunt.js`：画面をなぞって生き物を探し、見つけたら描画を止める（撮ったらページを開き直す）。

- 何本も同時に古い版を動かす時は、それぞれに `vite.capture.config.mjs`（`export default { cacheDir: '.vite-capture-cache' }`）を置いて `npx vite --config vite.capture.config.mjs` で起動する。共通の `node_modules/.vite` を取り合うと、真っ白な画面になることがある。
- `見本の家.geo.json`：建物の撮影に使った小さな家（赤い屋根・白い壁・煙突・花の窓）。

撮った素材は `docs/広報/素材/dayNN/` に置く（大きいので git には入れない）。1〜10・12〜17 日目は撮影済み。11 日目（軽量化）は、この PC では前後とも画面の上限 165fps で差が出ず、撮っていない。15 日目の魚は、魚が見つけやすい 1 つ後の版（8eb7ef1）で撮った。
