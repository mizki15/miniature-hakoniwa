## 1. 概要

ブラウザで動くボクセルの箱庭（ジオラマ）。自然の中を眺めることが中心で、畑・植林・地形の編集などで少しだけ手を加えられる。現実の時刻・全世界共通の季節と天気に合わせて箱庭が変化し、閉じている間も時間が進む。

| 項目 | 内容 |
|---|---|
| 動作環境 | PC のブラウザ（Chrome / Edge / Safari / Firefox の最近の版）。WebGPU、非対応なら WebGL2 で動く |
| スマホ | 閲覧のみ（パネル・モード切り替え・道具は出さない） |
| サーバー | 静的ファイルの配信だけ。処理と保存はすべてブラウザ内 |
| 技術 | TypeScript / Vite / three.js r187（WebGPURenderer・TSL） |
| 起動 | `npm run dev` → http://localhost:5173（本番ビルド：`npm run build`） |
| 同じ Wi-Fi の端末から | `npm run dev:lan` → https://（この PC の IP）:5173。WebGPU は https でしか使えないので自己署名の証明書で https にする（初回はブラウザの警告を「詳細 → アクセスする」で進む）。Windows のファイアウォールで Node.js の受信を許可しておく |

## 2. 画面構成

```
┌──────────────────────────────────────┬──────────┐
│ エディタ │（デバッグウィンドウ：メニューで出す）     │    [☰]   │
│ パネル   │                              ├──────────┤
│（エディタ）│       箱庭（画面いっぱい）         │ 図鑑      │
│ 道具・判定 │                              │（見る）    │
│ 土地の権利 │                              │ 時刻・季節・天気│
│          │                              │          │
└──────────────────────────────────────┴──────────┘
```

- 箱庭は画面全体に描き、パネルはその上に浮かぶ **すりガラス** の板
- パネルの色は時間帯で自動で切り替わる
  - 昼：明るいすりガラス＋濃い文字
  - 夜：暗いすりガラス＋明るい文字（空の暗さが 0.65 を超えたら夜、0.45 を下回ったら昼。間はそのまま）
- 右上：「☰」メニューのボタン（PC）
- 右のパネル（見るモード）：「📖 図鑑」。上に時刻・季節（手動なら「（手動）」）・天気を 1 行で出す（0.5 秒ごとに更新）。› でたためる
- 右のパネルの図鑑の上に、発見ポイントの数と、区画を開ける 30 までのたまり具合のゲージ（「区画を開くまで あと N」）
- 左のパネル（エディタモード）：上に Build｜Life｜Terrain の切り替え、その下にグループの道具の一覧（3.5）
- 画面下中央（エディタモード）：指している所の判定（「地面の高さがそろっていません」など）。何もない時は出さない
- 一時的なお知らせ（トースト）は画面下に数秒表示
- 狭い画面（幅 760px 以下）：左右のパネル・ホバー情報を出さず、画面下中央に「☰ メニュー」のボタンだけ出す。デバッグウィンドウは最初たたんだ状態

## 3. モードと操作

### 3.1 モード

| モード | キー | 表示 | マウス |
|---|---|---|---|
| 見る | Tab で切り替え | 右：図鑑 | 右ドラッグ：回転／中ドラッグ：移動／ホイール：ズーム（カーソルの位置へ）。左クリック：水面に波紋 |
| エディタ | Tab で切り替え | 左：エディタ、画面下：判定 | 左ドラッグ：道具を使う／右ドラッグ：回転／中ドラッグ：移動／ホイール：ズーム |

- 視点の動かし方は、見る・エディタで同じ（2026-11-22〜。右ドラッグで回す、中ドラッグで動かす）

- 起動時は「見る」
- Esc はメニューの開閉（モードは変えない）

### 3.2 キー一覧

| キー | 動作 |
|---|---|
| Tab | 見るモード ⇄ エディタモード（ブラウザのフォーカス移動はさせない） |
| 1 / 2 / 3（テンキーも） | Build・Life・Terrain のグループで、最後に使った道具に持ち替える（見るモード中に押すとエディタへ切り替わる）。2026-11-24 に Shift+1〜3 から変更（Shift 付きは何もしない） |
| R | 「建物を置く」の時、次に置く建物の向きを 90° 回す（透かした見本も回る） |
| Ctrl+Z（Mac は ⌘Z） | エディタで、最後の編集を取り消す（9.6 の下の「取り消し」参照） |
| Ctrl+Y・Ctrl+Shift+Z（Mac は ⌘⇧Z） | エディタで、取り消した編集をやり直す |
| Esc | メニューを開く・閉じる |
| W / A / S / D | カメラを前・左・後ろ・右へ水平に動かす（見ている向きが基準。速さは注視点までの距離 ×「移動の速さ」（デバッグウィンドウ、初期値 0.35）、最低 2） |

- 文字の入力欄・選択欄にフォーカスがある時は、キー操作を受け付けない（スライダーやボタンにフォーカスがあっても WASD は効く。Space でボタンが押されることはない）
- 移動キーは押す位置（e.code）で見るので、日本語入力が有効でも効く
- 注視点は開いた範囲から 24 より外へは出ない（高さは 0〜90）
- ブラウザの右クリックメニューは出さない（文字の入力欄だけは出す）
- メニューを開いている間は Esc 以外のキーを受け付けない

### 3.3 カメラ

| 項目 | 値 |
|---|---|
| 投影 | 透視投影、縦の画角 28°（ミニチュアらしさと奥行きのバランス） |
| 仰角 | 真上近く（5°）〜水平より下（105°、見上げる角度） |
| 距離 | 最短 3、最長 開いた範囲の一辺（縦横の大きい方）× 3.2。最初は開いた範囲の中心を見る |
| 初期位置 | 斜め上から全体が入る距離。縦長の画面では遠めから |
| 地面との関係 | カメラが地面（または水面）の 0.5 上より下に潜らない |
| 90° 回転 | デバッグウィンドウの「⟲ 90°」「90° ⟳」で、なめらかに 90° ずつ回る |
| 自動周回 | デバッグウィンドウの「自動周回」でゆっくり回り続ける |
| 近くの物 | カメラのすぐ近く（2.5〜9）の木・花・作物は、点描のように透けて視界をふさがない |

### 3.4 見るモードのホバー情報

- 対象は **作物・動物・訪問者・ホタル・建設中の建物だけ**（ふつうのブロックや苗木には出さない）
- 訪問者・ホタルは小さく速いので、画面上でマウスから 28px 以内のいちばん近いものを対象にする（動物・作物より優先）
- **観察**：まだ観察していない生き物（訪問者は、その季節にまだ観察していないもの）に 1.5 秒カーソルを合わせ続けると「〇〇を観察した！ +N」。カードに進み具合の輪と「観察中…」を出し、離れると 0 に戻る。固定中の対象も数える
- マウスの横に小さな情報カードを出す。作物のマスは水色の枠で示す
- **短い右クリック** で情報を固定（カードに「📌 固定中」）
  - 固定中は対象の横に表示し、動物が動けばついていく
  - 解除：短い右クリック（何もない所、または同じ物）。別の作物・動物なら固定先が変わる
  - 左クリックでは解除しない。右ドラッグ（視点の移動）では変わらない
  - 収穫などで対象がなくなったら自動で解除
- 水面を左クリックすると波紋が立つ

| 対象 | 内容 |
|---|---|
| 作物 | 名前、生育段階（芽が出た／若い／育ってきた／収穫できる）、湿り具合（水やり済み／水路のそば／雨でしっとり／乾いている）、収穫までの残り時間の目安、季節外れの注意、育ち具合のバー |
| 動物 | 名前、種類、いましていること（散歩中／ひと休み／眠っている）、好きなもの、得意なこと |
| 訪問者・ホタル | 観察前：「？？？」とヒント（名前は出さない）。観察後：名前・珍しさ（★〜★★★）・説明 |
| 建設中の建物 | 名前、組み上がったパーツの数、完成までの残り時間、進み具合のバー |

### 3.5 エディタモード

道具は 2 段で選ぶ：**左のエディタパネルの上の切り替え（または 1〜3 キー）でグループ**、**その下のボタンでグループの中の道具**。グループを替えると、そのグループで最後に使った道具（初めてなら一番上）に持ち替える。

- **グループ**：
  - Build：棚の建物（すべて）・片付ける。下に「📦 建物を読み込む・棚を見る」のボタン（9.6 の建物の窓を開く）
  - Life：耕す、カブ・小麦・かぼちゃの種、水やり、収穫、苗木、赤い花・黄色い花・白い花、木を切る
  - Terrain：掘る、整地、土の道、石畳、ブロックを置く（土・石・砂・丸太・葉・針葉。草地のブロックは無く、土から草が生える。8.4）
- **道具のボタン**：アイコンと名前だけ（選んでいる物は緑）。説明は、ボタンにカーソルを合わせて「説明が出るまで」（デバッグウィンドウ、初期値 0.2 秒）たった時だけ、パネルのすぐ右に出す。離すと消える
- 指しているマスに枠を表示：使える所は白、使えない所は赤（理由を画面下中央に表示）
- **左ドラッグでなぞった所にまとめて使う**
  - 数ピクセルおきに判定するので、速く動かしても抜けない
  - 1 回のなぞりで同じ列には 1 回だけ（掘りすぎ・積みすぎ防止）
  - なぞっている間も枠はマウスについていく（使った直後のマスが赤く見えないよう白のまま）
  - 終わると「◯ マスに「耕す」を使いました」のようにまとめて知らせる

| 道具 | 使える所 | 結果 |
|---|---|---|
| ⛏ 耕す | 草地か土の上面（その列の一番上）。木の根元・耕し済みは不可 | 畑（耕した土）にする。その列の花は消える |
| 🌱 種まき | 畑で、まだ何も植えていない所 | 選んだ種をまく |
| 💧 水やり | 畑 | 6 時間（箱庭内の時間）湿らせる。湿っている所にもう一度やると延長 |
| 🧺 収穫 | 育ちきった作物 | 持ち物に 1 つ加える（小麦はわらも 1）。育ちきっていなければ育ち具合を表示 |
| 🌳 苗木 | 草地か土の上面。まわり 1 マス以内に木があると不可 | 苗木を植える（高い所＝高さ 20 以上は針葉樹） |
| 🌹 花を植える | 草地の上面。木の根元・もう花がある列は不可 | 選んだ色（赤・黄・白）の花を植える。花の数は生き物の来やすさに効く（7 章）。植えた花は保存する |
| ✂ 摘む・刈る | 花のある列、葦の生えた泥の列 | 花を摘む（花 +1。生成された花も消えたまま保存）／葦を刈る（葦 +1。3 日で生え戻る） |
| 🪓 木を切る | 育った木（自然の木と、植えて育ちきった木）。指した所の手前にある木を選ぶ（木は「根元〜てっぺん、葉の広がりの 7 割」の箱で見る）。育っている途中の苗木は不可 | 丸太 3 本（広葉樹か針葉樹）と葉・つる 2 を持ち物に加える。木はその場で若木（育ち具合 0）に戻り、また約 1 日で育つ（切り株から育つ） |
| 🕳 掘る | 一番下（高さ 0）以外のブロック。育った木の根元は不可（先に木を切る）。育っている途中の苗木の根元は可 | ブロックを消して原料にする（草地・土・畑・土の道 → 土、岩・石畳 → 石、砂 → 砂、泥 → 粘土、丸太 → 広葉樹の丸太、葉 → 葉・つる）。岩を表面から 3 段以上深く掘ると 12% で鉄鉱石も出る。苗木の根元なら苗木ごと。水のそばを掘ると水が流れ込む（湿地の泥を掘ると池になる）。切った自然の木の根元を掘った列には、読み込み直しても生成した木は戻らない |
| 📏 整地 | 列の地面（面の向きは問わない）。木・作物・建物の列、高さの差が 8 段を超える列は不可。なぞっている途中で側面に当たり、当たった列がもうそろっていて、面の向こうの低い列（へこみ）がまだなら、へこみの列を選ぶ（底にカーソルが届かなくても壁を指せば埋まる） | なぞり始めた列の地面の高さに、なぞった列を削る・盛る。削った分は原料になり、盛る分は土を使う（足りない列は盛れない）。表面の草地・砂は残し、畑は土に戻す。削って水のそばになれば水が流れ込む |
| 🛤 道を敷く | 草地・土・砂・畑の上面（作物・木の列は不可） | 一番上のブロックを「土の道」か「石畳」にする（石畳は石を 1 使い、石畳から土の道にすると石が戻る）。畑だった所は畑でなくなる。住人は道を好んで歩く（行き先を選ぶ時、道の上の候補を優先する） |
| 🧱 ブロックを置く | 指した面の隣が空気か水。上から 2 段・外周の外・木の列は不可 | 選んだブロック（土・石・砂・丸太・葉・針葉）を置く。原料を 1 使う（土 → 土、石 → 石、砂 → 砂、丸太 → どちらかの丸太、葉・針葉 → 葉・つる）。無ければ置けない |
| 🏠 建物を置く | 地面の上面。足元がすべて開いた区画にあり、高さの差が 1 段まで・原点の列より高い列がない（めり込まない）所。木・作物・水の上と、ほかの建物と重なる所は不可 | 素材と発見ポイントを払って（9.8）、選んだ建物の建設を始める（9.6 参照）。足りなければ置けない（足りない素材を出す）。足元の花は消える。1 回のなぞりで 1 棟 |
| 🧹 片付ける | 置いた建物（外形の箱に当たったもの。建設中も） | 箱庭から取り除く（棚には残る）。払って建てた建物は、素材と発見ポイントを全部戻す（取られるのは時間だけ） |

- 建物（建設中も）の足元の列と、光線が地形より先に建物の外形に当たる所には、建物以外の道具は使えない（「建物があります」）
- 道具は開いた区画の中だけで使える（開いていない区画には土を盛れず、掘った穴の水も開いていない区画へは流れない）
- **建物を置く時の見本**：置こうとしている場所・向きに、建物を少し透かして（不透明度 0.55）表示する。置けない所では赤みを帯び、枠も赤い。置くと不透明になる
- **取り消し（Ctrl+Z）**：1 回のなぞり（またはクリック）を 1 つとして、新しい順に最大 50 回まで戻せる
  - 戻すもの：地形（掘った所に流れ込んだ水も）、畑・作物・水やり・持ち物、苗木、植えた花・消えた花、切った木、置いた・片付けた建物
  - 両方にある作物・苗木・建物は、今の育ち具合・建設の進み具合のまま（取り消しで時間は戻さない）
  - 戻さないもの：区画を開くこと、棚への出し入れ。箱庭を作り直したり読み込んだりすると、記録は消える
- **やり直し（Ctrl+Y・Ctrl+Shift+Z）**：取り消した編集を、取り消した順の逆にやり直す（最大 50 回）。取り消す直前の状態を同じ形の記録にして覚えておき、それに戻す。やり直した物はまた取り消せる。取り消した後に新しく編集すると、やり直しの記録は捨てる
  - なぞっている最中・見るモードでは効かない。文字の入力欄では、ブラウザ自身の取り消しになる
- **区画を開く**：エディタモードでは、開いた区画に上下左右で接する空き区画が半透明の枠で出る（高さ 12 の箱。上端が、となりの開いた区画の地面の平均より 4 下）。枠をクリックすると発見ポイントを 30 使って開く（4.1 参照）
  - 開く前に、区画の土地の型をアイコンで見せる（🌳 森と草原・🪨 岩場が多い・🪷 湿地がある・🏖 砂浜がある。枠の上、暗い半透明の丸）。枠を指すと画面の下にも一言（例：「🪷 湿地がある・クリックでこの土地を開く」）。版 1 の箱庭では出さない
  - 枠に合わせると画面下に「クリックでこの土地を開く（発見ポイント 30）」、足りなければ「発見ポイントが足りません」と出る（足りない時は枠の線が灰色）
  - 開いた区画は 0.6 秒で下からせり上がり、木と花はせり上がった後に現れる。「新しい土地が開きました」と知らせる
  - 開いている途中にもう一度押しても、2 つ目は開かない
- 種：🥬 カブ（1.5 時間）、🌾 小麦（6 時間）、🎃 かぼちゃ（8 時間）。種のボタンを押すと種まきの道具になる
- 畑を掘ったり上に土を盛ったりすると、その列の作物と畑は消える（上に盛った時、下の畑は土に戻る）

## 4. 箱庭（地形）

### 4.1 大きさ

| 項目 | 値 |
|---|---|
| 枠 | 320×320（いつもこの大きさでデータを持つ。v0.13 までは 256×256） |
| 区画 | 64×64 を 5×5 = 25 区画。区画の番号は `px + pz×5` |
| 最初の区画 | 真ん中の (2,2)（番号 12）だけ。開ける土地は、最初の区画を中心にした 5×5 まで（4 方向に 2 区画ずつ） |
| 高さ | 64 ブロック（地表は最大 58） |
| 水面の高さ | 10（この高さより下の空いている所が水） |
| 台座 | 開いた区画ごとの木の板（厚さ 2.4）。隣が開いていない側だけ 1.5 はみ出す。1 つのメッシュにまとめて描く。空島（版 3）には出さない |

- まだ開いていない区画は空気だけ（地形も水もない）。開いた区画の外側の面には地層の断面が見える
- **発見ポイント**（v0.14〜。土地の権利をなくし、ポイントに一本化した。10 倍の整数）：区画を開く＝30、建物＝大きさに応じて 2〜15。入るのは、初めての観察（ふつう 10・ややまれ 20・まれ 40）、訪問者を新しい季節に観察（10）、訪問者が来るたび（2）
- 右パネルに「✨ 発見ポイント」とゲージ（区画を開ける 30 まで）
- 区画を開くと、ワーカーがその区画を作り、その区画と、接している開いた区画のメッシュを作り直す（1 区画あたり約 130 ms。その間も画面は動く）

### 4.2 ブロックの種類

| 番号 | 種類 | 備考 |
|---|---|---|
| 0 | 空気 | |
| 1 | 草 | 上面の色は季節で変わる。側面は濃い緑、下面は土色 |
| 2 | 土 | |
| 3 | 岩 | |
| 4 | 砂 | |
| 5 | 水 | |

### 4.3 地形の作り方

シード値（整数）から決定論的に作る（同じシード・同じ設定なら同じ地形）。

**区画をどの順番で開いても、最初から全部作った時と同じ地形になる**ように、どの列の高さ・地表・木・花も「枠の座標とシード値」だけで決める（順番に乱数を引かない。座標から決まるハッシュ乱数 `hash2` を使う）。

1. **高さ**：ノイズの重ね合わせ
   - 細かな丘：12.5 ＋（fbm × 7 ＋ 丘 × 9）× 起伏の激しさ
   - 大きな起伏：最大 22 × 山の高さ
   - 湖：低い周波数のノイズで窪地を作る（水の多さで広さが変わる）
   - 川：X 方向に蛇行する 1 本。中心は場の座標 z = 96（最初の区画の真ん中）なので、最初の区画を必ず流れる（水の多さ 0.15 以下・川の幅 0 なら作らない。幅は水の多さと川の幅で変わる）
   - **場の座標**：ノイズとハッシュは「枠の座標 − 64」で引く（v0.14〜の 5×5 の枠でも、最初の区画とその周りが v0.13 までと同じ地形になるように）
   - 高さは 3〜58 に収める
2. **地表の種類**（同じ高さでも混ざる）
   - 水面以下・水辺（水面＋2 まで）の一部 → 砂（砂浜が内陸に入り込む）
   - 高さ 35 以上、または岩場のノイズ → 岩
   - 土がむき出しのノイズ → 土
   - それ以外 → 草
   - 地表の下 3 段は土（岩場の下は岩）、さらに下は岩
3. **水**：水面より下で空いている所を水で満たす
4. **木**：草地（水面＋2 より上）が候補。森のノイズが濃い所は多く、まばらな所は少なく（森の密度で増減）。候補のうち、まわり 5×5 の候補の中でハッシュ値がいちばん大きい列だけに置く（木同士は 3 マス以上離れ、区画の境目でも同じ）。枠の端 2 列には置かない。高さ 20 以上は 75%、それ以外は 15% が針葉樹
5. **花**：草地（木の根元以外）に置く。花畑のノイズが濃い所に多く（花の密度で増減）。1 マスの中で位置・向き・大きさをばらつかせる
6. **区画ごとの土地の型**（地形の作り方の版 2。v0.13〜の新しい箱庭）：最初の区画はふつう。残りの 24 区画に、岩場 6・湿地 6・砂浜 5・ふつう 7（デバッグで変えられる）をシードで並べる（`src/world/landPlan.ts`）。型の強さは区画の中ほどで 1、境目の近く（端から 1/4）だけでとなりとなめらかにまざる
   - 岩場：岩が突き出て崖になり（最大 +16）、岩の地表が広がる
   - 湿地：低い所（水面＋6 まで）を水面すれすれにならし、ところどころ深さ 1 の水たまりにする。地表は泥（新しいブロック。歩ける）。水たまりの底も泥
   - 砂浜：入り江ができやすく、水辺の近くを低く平らにし、砂を内陸まで広げる
   - 区画の数は標準で岩場 6・湿地 6・砂浜 5・ふつう 7（v0.13.1 で 5×5 に）。自然な地形の割合（5 つのシード）：ふつうの区画 森 10%・草原 29%・砂浜 17%・岩場 10%。岩場の区画 岩場 39%。湿地の区画 湿地 51%。砂浜の区画 砂浜 35%・深い水 23%
   - **版 1**（v0.12 までに作った箱庭。保存の地形のパラメータに `land` が無い）は、前と同じ地形のまま作る（差分がずれないように。テストで固定）。v0.13〜v0.14 に作った箱庭は版 2 のまま
7. **空島**（地形の作り方の版 3。v0.15〜の新しい箱庭。試作）：開いた土地が空に浮く島になる（`src/world/terrain.ts`）
   - 縁：列の中心から、いちばん近い開いていない区画（枠の外も含む。8 近傍）までのユークリッド距離 d（上限 40）を出す。d < 縁のしきい値（4〜14 列 × 縁の削れ方。ノイズで揺れる）の列は空（高さ 0・歩けない・木と花なし）。距離をユークリッドで取るので、角は丸く削れる
   - 縁の内側 4 列は、水面より低ければ水面＋1 の砂に持ち上げる（水が縁からこぼれない）
   - 底：縁に近いほど薄い（厚さ 3 ＋ 縁からの距離 × 1.1 ＋ ノイズ、× 島の底の厚さ）。それより下は空で、内側は y = 0 まで埋まる。台座は出さない
   - 区画を開くと、開いている 8 近傍の区画のうち、開く前の d が 40 未満の列を作り直す（縁が新しい区画の方へ広がる）。空だった列に出た木と花だけを足す。木と花は削る前の列で決まるので、順に開いても、最初から全部作っても、同じ地形・同じ木と花になる（テストで固定）。区画を開いた結果は、区画 ±1 区画の範囲を書き戻す
   - 岩場・湿地・砂浜は、区画でなく低い周波数のノイズ（110 列 × バイオームの大きさ）で広がる。区画の数のスライダーは広さ（しきい値 0.6 − 数/24 × 1.2）。区画のアイコンは出さない

### 4.5 小物（木・花）

- 地面とは別の細かいボクセルで作り、インスタンス描画（同じ形を大量に描く）。種類ごとに 1 つの InstancedMesh にまとめる（全部の区画をまとめた方が、描画命令が少なく速かった）
- 細かさ（デバッグ「小物」）：地面のボクセルに対して **1/1・1/3（標準）・1/4**
- 形は地面の単位の連続的な形として定義し、細かさで標本化する（細かさを変えても同じ形・大きさ）
- **木**：6 種類
  - 広葉樹 4 種：幹（上に行くほど細い）＋ノイズで揺らした球を重ねた樹冠。細かいボクセルの時は枝も
  - 針葉樹 2 種：段々になった円すい。冬は上面に雪
  - 向き（90° 単位）と大きさ（0.85〜1.2 倍）をばらつかせる
- **花**：赤・黄・白の 3 種
  - ローポリ（標準）：茎・葉・花びら 5 枚・花芯
  - ボクセル：細かさ 1/3 以上の時だけ作れる（1/1 の時はローポリになる）
  - 冬は表示しない
- **地面の小石と草**（2026-11-22〜）：ローポリの小さな石と草の房を、ところどころに置く。花と同じく下のブロック（列の一番上）に付いた見た目だけの物で、建物・道具・住人の判定には関わらない
  - 小石 3 種（1〜3 個の石の集まり、灰色〜茶色）、草の房 3 種（4〜8 本の細い葉。色は季節の草の色。風で揺れる）。向き・大きさ（0.8〜1.25 倍）・ブロックの中の位置をばらつかせる。影は落とさない
  - 置き場所は列ごとのハッシュで決める（いつも同じ所に出る）。出やすさ（多さ ×1 の時、1 列あたり）：草地 草 14%・小石 1.5%、土 草 4%・小石 5%、岩 小石 10%、砂 小石 4%。人工物（道・石畳・畑・丸太）、水の下、木・苗木・建物・花のある列には置かない
  - 掘る・積む・建物を置く・花や苗木を植えるなどで地面が変わると、0.3 秒ほどで置き直す（開いた区画は、せり上がりが終わってから）
  - 多さはデバッグ「石と草の多さ」（0〜4、初期値 1。0 で出さない）。この端末に覚える（localStorage `hakoniwa.groundDensity`）
- **風**：根元からの高さに応じて揺れる（2 つの周期を重ねたゆったりした動き、先端で最大 0.25）。花は背が低いので高さに比例した揺れも足す。天気で風の強さが変わる

### 5.1 地形のシェーダー

| 機能 | 内容 |
|---|---|
| 頂点 AO | ブロックの隅を暗くする（メッシュを作る時に計算） |
| 境界のなじませ | 同じ平面上の隣の面の色を、ノイズで揺らした双線形補間で混ぜる（違う種類のブロックの境目をぼかす。違う平面とは混ぜない）。強さはデバッグ「境界のなじみ」（0 = くっきり〜1 = なめらか）。人工物（石畳・丸太・土の道・畑）は混ぜない：人工物の面はとなりの色を取らず、自然物の面も人工物の色を取らない（境目がくっきり） |
| 角丸（ベベル） | 法線を縁で曲げて丸く見せる（形は立方体のまま）。段差の外側の角は外へ、入り隅は壁から離れる向きへ。同じ平面の継ぎ目は曲げない（溝ができない）。デバッグ「角丸」で ON/OFF |
| 地面の質感（バンプ） | 形は平らな箱のまま、ブロックの種類ごとの模様で法線を少し傾け、光の当たり方だけを細かく変える（2026-11-22〜）。草地：細かい毛羽立ち、土：粒とくぼみ、岩：土のようなザラザラ（土より少し粗く強め）、砂：細かい粒とゆるい風紋、石畳：石の目地のへこみと石ごとの傾き（ブロックの半分の石を段ごとに半分ずらす）、丸太：上下の面は年輪・側面は縦の樹皮の筋、土の道：細かいざらつき、畑：上面の畝の溝、葉：ざらつき。ノイズは 1 ピクセルにつき 1 回（種類で細かさを変えて共有）、ほかの模様は式で作る。カメラから 18〜70 で弱めて消す（遠くのちらつき防止）。強さはデバッグ「地面の質感」（0〜1、初期値 1、0 でなし。保存しない）。画質「低」では描かない |

| 季節の色 | 草の上面の色を季節で変える（冬は雪） |
| 雪 | 冬は上向きの面すべてに積もる。高さ 41〜47 から上は一年中（上向きの面は濃く、側面は薄く） |
| 畑 | 上面に畝の筋 |
| コースティクス | 水面より下の上向きの面に、揺らめく光の模様（外周の断面には出さない） |
| 雲の影 | 上空の雲の模様に合わせて地面を暗くする（流れる） |
| ホタルの光 | 近くのホタルが地面や草木をほんのり照らす。光っているホタルがいない時（昼・ホタルが来ていない時）は、1 画素ごとの 32 匹ぶんの計算を飛ばす（どの画質でも） |

### 5.4 ポストプロセス

| 効果 | 内容 | ON/OFF |
|---|---|---|
| AO（画面空間） | GTAO（半分の解像度）＋ノイズ除去。強さ 0〜1.5（標準 1） | デバッグ「AO」「強さ」 |
| 被写界深度 | 画面中央の奥行きにピントを合わせ、なめらかに追従。f 値 1.4〜22（標準 5.6）。空はぼかさない | デバッグ「被写界深度」「f値」 |
| ブルーム | 明るい所（ホタル・照り返し）がにじむ | デバッグ「ブルーム」 |
| トーンマッピング | ACES Filmic | 常時 |
| アンチエイリアス | 下の 6 つから選ぶ（標準 FXAA）。画面そのもの（canvas）には MSAA をかけない | デバッグ「アンチエイリアス」 |

- 順番：場面を描く →（TRAA・TAAU）→ AO → 被写界深度 → ブルーム →（FXAA・SMAA）
- アンチエイリアスの方法（2026-11-21。保存しない）：

| 方法 | 内容 |
|---|---|
| なし | いちばん軽い。ふちがギザギザ |
| MSAA 4x | 場面を描く時に 1 画素を 4 か所で調べる。形のふちだけ効く。色・法線・深度の分がすべて 4 倍になるので、解像度が高いほど重い |
| FXAA | 描き終わった絵のふちをぼかす。軽いが少しぼやける |
| SMAA | ふちの形を調べてから混ぜる。FXAA より少し重く、くっきり |
| TRAA | カメラを毎フレーム少しずらし、前のフレームと混ぜる。動きの向き（速度）も一緒に描く。動いた物・風で揺れる草は少し残像が出る |
| TAAU | TRAA と同じことを、低い解像度で描いた絵から元の解像度へ広げながら行う。「描く解像度」を下げる時に使う |

- **描く解像度**（100%・75%・50%）：場面を描く解像度（画面の画素に対する割合）。下げるほど軽い。どの方法とも組み合わせられる
- 「測る」：今の設定で 60 フレーム描き、1 フレームの時間を出す（ベンチマーク）

### 5.5 画質プリセット（デバッグ「画質」）

| 項目 | 高 | 中 | 低 |
|---|---|---|---|
| 解像度の倍率 | 端末の倍率（最大 2） | 最大 1.25 | 最大 1 |
| AO | ○ | ○ | × |
| 被写界深度 | ○ | ○ | × |
| ブルーム | ○ | ○ | × |
| 影の解像度 | 4096 | 2048 | 1024 |
| 地形のシェーダー | 通常 | 通常 | 簡略（境界のなじませ・角丸・地面の質感なし） |

- **自動**（標準）：WebGPU なら「高」、WebGL2 やスマホなら「中」から始める。0.5 秒ごとの fps を 2 秒ぶん集め、中央値が 40fps 未満なら下げる（上げることはしない）
  - 25fps 未満なら「中」を飛ばして「低」へ（「中」は解像度が違うだけなので、等倍の画面ではほとんど軽くならない）
  - 画質を変えた直後・箱庭を作っている間の 1.5 秒は数えない（シェーダーの準備で一瞬重くなるため）。中央値なので、一瞬の引っかかりでは下がらない
- 画質を変えても、畑や地形の変更は保ったまま作り直す

### 5.6 描き方（デバッグ「描き方」：ふつう／トゥーン・高／トゥーン・軽。試作。v0.15.1〜v0.15.2）

- **トゥーン・高**：スタイライズした軽い描き方。少し線画風。この端末に覚える（`hakoniwa.renderStyle`）。切り替えはマテリアルを差し替えるだけ（箱庭は作り直さない）
  - 地形・木・花・建物：光を 3 段に分ける（`MeshToonNodeMaterial`。ハーフランバートで 0.5・0.78・1）。地形は「低」と同じ簡略（ボクセルの種類の読み出し 1 回、境界のなじませ・角丸・質感の凹凸なし）に加え、ノイズの色むらと水中のコースティクスも省く。頂点の AO・雲の影・ホタルの光・雪・夜の窓の灯りはそのまま
  - 水：画面の読み返し（屈折・水の厚み・岸の泡）をせず、半透明（0.82）の平らな塗り。斜めから見るほど空の色（2 段）、ゆっくり流れる白い波の線、昼夜で明るさだけ変える
  - 線画（後処理。`src/render/toon.ts`）：深さの 2 階差分で輪郭（平らな面は斜めでも線にならない）、となりの画素との法線の差でブロックの角。線は黒ではなく、その場所の色を暗くした色。遠く（140〜420）は薄く、空には描かない。濃さはスライダー「線」（0〜1.5）
  - AO は使わない。被写界深度とブルームは、切り替えた時に切る（チェックで戻せる）。影はそのまま
- **トゥーン・軽**（v0.15.2）：トゥーン・高に加えて、次を減らす
  - 影：影の地図を 1024 まで、描き直しを 4 フレームに 1 回（デバッグの間引きがそれより粗ければ、そちら）
  - 遠くの形：花・草・作物・苗木は、カメラから 90 より遠いと根元へ縮めて地面の下にしまう（68〜90 で少しずつ）。木は箱庭の見た目の要なので残す（全体を見る距離で木が全部消えてしまうため）
  - 描く解像度：場面を 75% で描く（線画と FXAA で輪郭はつぶれにくい）
  - 空：雲のノイズを 4 段 → 2 段、星を 2 層 → 1 層。地形・小物の雲の影のノイズを 3 段 → 1 段

## 6. 時間・季節・天気

### 6.1 時刻（昼夜）

- 端末の現在時刻と連動（デバッグ「時刻」スライダーで上書き、「現在」で戻す）

### 7.5 土地の型の割合と野生度（v0.11）

- 開いた区画の列（水面も含む）を、1 列ずつ 1 つの土地の型に分ける。先に当てはまったものを取る
  1. 水面：水の列。分母には入るが、条件には使わない
  2. 水辺：水から 2 列以内（5×5）の列
  3. 畑：耕した列
  4. 人の手：道（土の道・石畳）と建物の足元
  5. 森：木（苗木も）の根元から 2 列以内（5×5）
  6. 花畑：草地で、まわり 3×3 に花のある列が 2 つ以上
  7. 草原：残りの草地
  8. そのほか（土）
- v0.13 で順番を「水面（底が泥の水たまりは湿地）→ 人の手 → 畑 → 湿地（泥）→ 水辺 → 砂浜（水辺より外の砂）→ 岩場（水辺より外の岩）→ 森 → 花畑 → 草原」に変えた（水辺の道や畑も、野生度に数える）
- 割合＝その型の列 ÷ 開いた区画の列。深い水（地面が水面より 3 以上低い列）は水面の中から別に数える
- 自然な地形ではおよそ 森 4〜10%・草原 17〜25%・花畑 3〜6%・水辺 11〜14%・水面 23〜42%（5 つのシードで測った）。条件の数値はこれに合わせたたたき台
- **野生度**（★1〜★5）：畑・道・建物の足元の合計の割合が 2% 未満 ★5・5% 未満 ★4・10% 未満 ★3・20% 未満 ★2・それ以上 ★1
  - 建物の足元は、その建物の自然の星で重み付けして数える（(6 − 自然の星) ÷ 5。★5 のかやぶきの家は足元の 2 割、★1 は全部）。性格がまだ計算できていない建物は足元をそのまま数える（v0.12）
- **灯りの届かない水辺・森**（v0.12）：建ち終わった灯りのある建物（9.7）の足元の中心から、灯りの届く距離（灯りの星 1 で 4 列、星 1 つごとに +2 列）の円の外にある水辺・森。ホタルは灯りの届かない水辺 5%、フクロウは灯りの届かない森 40% が要り、灯りの届く所には現れない
- **星で見せる**：割合が 5・10・20・30・40% 以上で ★1〜★5
- 取り合いになる組（テストで固定）：しか と たぬき・フクロウ・キツツキ（森の割合）、きつね と フクロウ、スズメ と カワセミ（畑を 5% にすると野生度が ★3 以下になる）
- 数え直すのは、地形を変えた・区画を開いた・作物や苗木や建物が変わった時だけ（16 区画で 1 回 約 4 ms）

### 8.4 放っておくと変わる景色（v0.13。`src/game/nature.ts`）

- **土から草が生える**：掘る・盛る・整地などで表面がむき出しの土になった列は、箱庭の時計で 1 日たつと草地になる（畑・建物の足元・水面より下は除く）。生成された土の地面は変わらない。v0.12 までの保存は、読み込んだ時点から数え始める

  - 木（苗木も）1 本ごとに 2.5% の確率で、根元から 2〜3 列の草地に苗木が生える（となりに木がない・畑・作物・建物がない・水面より上の列だけ）。苗木は植林と同じく 24 時間で木になる（草原 → 小さな木 → 森）。1 か月で森の端がはっきり広がるくらい
  - 花は 1 日に 1% の確率で枯れて草地に戻る（花畑 → 草原）。枯れた生成の花の列は保存して、読み込んだ時に消し直す
  - 岩場・湿地・砂浜は変わらない（苗木は草地にしか生えない）。伐採の道具で苗木を切れば、草地のまま保てる
- プレイヤーの操作ではないので、Drive 同期の「変更」の印は立てない（保存はする）。なぞっている途中は待つ（取り消しの記録に混ぜない）
- 保存：`farm.bare`（むき出しの土の列と時刻）、`farm.faded`（枯れた生成の花の列）、`farm.natureDay`（最後に進めた日）

## 9. 保存

### 9.1 セーブデータ

- 地形はシードから作り直せるので、**生成の設定＋変えた所（差分）＋畑の状態** だけを保存する
- JSON を gzip で圧縮。例：畑 8 マス・作物 8・苗木 1 で約 0.3 KB
- 形式のバージョン（現在 4）を持ち、古い形式を読む仕組み（migrate）がある。新しいバージョンのデータは読まずに知らせる
- **v3 → v4**（v0.13.1）：枠を 256 から 320 に広げ、最初の区画を真ん中に移した。開いた区画・差分のボクセルの番号・畑や苗木などの列・住人と建物の位置を、1 区画（64 列）ずつ右下へずらして読む。地形は場の座標で作るので、ずらした所に前と同じ地形ができる
- **v1（大きさを選んで作っていた頃）のデータは引き継がない**：地形の作り方が変わったため。読もうとすると「保存データは古い形式のため新しく始めます」と知らせて、新しい箱庭を作って保存する

| 中身 | 内容 |
|---|---|
| version / savedAt | 形式のバージョン、保存した現実の時刻 |
| world | シード、高さ、小物の細かさ、花の種類、地形のパラメータ |
| plots | 開いた区画（25 ビットのマスク） |
| edits | 変えたボクセル（番号と種類の組。番号は 320 の枠の座標） |
| progress | 使える発見ポイント（v5〜。使った権利の数の欄は 0。解放済みのもの・初めての実績・「新」の印の欄もあるが、段階 ③ まで空） |
| dex / residents | 図鑑（種類ごとに見かけた時刻・観察した時刻・観察した季節）と住人（種類・場所・名前）。訪問者は保存しない |
| farm | 箱庭内の時計、持ち物（作物・原料・素材。素材は「m:」＋パレットの名前）、作物（列・種類・育ち具合）、苗木（列・種類・向き・育ち具合。切った自然の木も、ここに若木として入る。読み込む時、苗木のある列の自然の木は消す）、湿っている期限、植えた花（列・色。無ければ無し） |
| buildings | 建物の棚（検査済みの形：名前・直方体ごとの行列と色・外形。元の JSON は持たない）と、置いた場所（建物・列・向き）。v2 のデータは空の棚として読む |

- 保存しないもの：画質・時刻や季節や天気の上書き・カメラ位置などのデバッグ設定

### 9.2 保存先とタイミング

| 保存先 | タイミング・操作 |
|---|---|
| この端末（IndexedDB） | 自動：変更があれば 1 分ごと（早送り中も 1 分ごと）、なくても 5 分ごと、ページが隠れる・離れる時。メニュー「今すぐ保存」 |
| ファイル（.hakoniwa） | メニュー「ファイルに書き出す」「ファイルから読み込む」 |
| Google Drive | Google でログインすると自動（PC：編集するたびに、手が止まって 3 秒後・ページが隠れる時。窓に戻った時と開いている間は 1 分ごとに Drive を見て、別の端末で進んでいれば追いつく。スマホ：読むだけ）。メニュー「今すぐ同期」（アプリ専用フォルダ、要設定） |

- 初めて保存する時に、ブラウザへ「消さないで」（永続化）を頼む。断られたらメニューに「書き出しで控えを」と表示
- 保存は 1 つ（main）だけ

### 9.3 読み込み

- 起動時、この端末に保存があれば読み込む。なければ新しい箱庭を作って保存する。読めなかった時は新しい箱庭を作って知らせる
- 差分はワーカーで地形に当ててからメッシュを作る（変えた列の花は取り除く）
- **閉じていた間の成長（オフライン進行）**：閉じていた時間（最大 7 日）を 15 分ずつ、その時々の季節・天気（雨なら畑が湿る）で進める。3 分以上たっていれば「おかえりなさい。◯時間たちました：◯ マスの作物が実りました・◯ 本の木が育ちました」と知らせる
- ファイル・Drive から読み込む時も同じ（今の箱庭に変更があれば上書きの確認をする）

### 9.4 作り直しと上書きの確認

| 操作 | 今の箱庭 |
|---|---|
| 「生成」ボタン（新しい箱庭。最初の区画だけ・権利 0 から） | 変更（地形・畑・苗木）があれば上書きの確認。キャンセルで元に戻す。作ったらすぐ保存 |
| 小物の細かさ・花の種類・画質（地形の簡略化）の変更 | 保ったまま作り直す |

### 9.5 Google Drive 同期

- ブラウザから直接 Drive API を呼ぶ（サーバーなし）。スコープは drive.appdata（アプリ専用の隠しフォルダ、他のファイルは見えない）。ファイルは `hakoniwa-save.bin` の 1 つ
- 認証は Google Identity Services のトークンモデル。アクセストークン（約 1 時間）は sessionStorage にだけ置く（タブを閉じれば消える）。ポップアップを出すのはボタンを押した時だけ
- メニューの「💾 保存」に状態を出す：ログイン前（「Google でログイン」）／ログイン中（アカウントと最後に同期した時刻、「今すぐ同期」「ログアウト」）／期限切れ（「タップして同期を続ける」。起動時にトークンがなければこれになり、知らせる）
- **何をするかの決め方**（`src/save/syncDecision.ts`）：保存時刻どうしは比べない。端末ごとに「最後に同期した Drive の版（印）」と「その後にプレイヤーが手を加えたか（変更の印）」を localStorage に残して決める
  - Drive が変わっていない：変更があれば送る、なければ何もしない
  - Drive が変わった：変更がなければ黙って読み込む、あれば「両方で変わっています」と聞く（読み込む／この端末の箱庭で上書き。上書きはもう一度確認）
  - 初めての端末：Drive になければ送る。あれば、手が入っていなければ読み込み、入っていれば聞く
  - 変更の印を立てるのは、道具を使った・元に戻した・建物を棚に足した／外した・区画を開いた・作り直した・ファイルから読み込んだ時。時間の経過や生き物の発見では立てない
  - この端末に箱庭がなく新しく作った時は「初めての端末」に戻す（作っただけの箱庭で Drive を上書きしない）
  - **印は「最後に同期した箱庭の保存時刻」**（v0.14.1〜。`s:<保存時刻>`。保存時刻は Drive のファイルの appProperties.savedAt に入れてある）。Drive の版の番号はサーバー側の処理でも勝手に進むので、それで比べると、何も変わっていないのに読み込み直したり「両方で変わっています」と聞いたりしていた。前の版の印（版の番号）も一度だけ受け付ける
  - **箱庭を作り直している・読み込んでいる間は同期しない**（1 秒後にやり直す）。デバッグの「生成」は、作り始める前に変更の印を立てる（作っている数秒の間に同期が走っても、Drive の古い箱庭で黙って上書きしない）
  - **読み込んでいる間に手を加えたら**、読み込んだ箱庭で上書きせず、もう一度決め直す（Drive も変わっていれば聞く）
- **スマホ**（タッチ操作で画面の短い辺が 820 未満）：Drive へは書き込まない。ログイン中は見るだけ（エディタに入れない）。初めてログインした時に手の入った箱庭があれば「Drive の箱庭に入れ替えますか？」と聞き、断るとログインを取りやめる。アプリに戻った時に Drive が変わっていれば読み直す
- ログアウト：トークンを取り消し、アカウントと同期の印を消す。この端末の箱庭はそのまま
- Client ID は環境変数 `VITE_GOOGLE_CLIENT_ID`（`.env.local`、公開版は Cloudflare Pages の環境変数）。未設定なら「この版では Google 同期は使えません」と出す
- 同期の流れ（`src/save/cloudSync.ts`）は偽の Drive でテストしている。**実際の Google との通信は、Client ID を作ってから確かめる**

### 9.6 建物の読み込み

設計：[docs/superpowers/specs/2026-11-19-building-import-design.md](superpowers/specs/2026-11-19-building-import-design.md)

- 形式は **Blockbench の Bedrock 形式（.geo.json）**。直方体（cubes）とグループ（bones）だけを読み、`uv`・テクスチャなどは無視する。`poly_mesh` はエラー
- 座標：16 単位 = 1 マス。Bedrock 形式は X が反転しているので、Blockbench の画面の座標に戻して使う（回転は `[-x, -y, z]`、順番は ZYX。pivot は絶対座標）。底は y = 0 にそろえる（±0.5 単位まで許し、ちょうど 0 にずらす。膨らみ inflate は判定に入れない）
- 色：グループ名がパレットの名前か「名前_何か」ならその色、違えば親の色。13 色（wall・wood・plank・roof・roof_blue・thatch・stone・brick・white・glass・dark・leaf・flower）
  - 名前は NFKC で正規化してから照らし合わせる（全角の ｇｌａｓｓ は glass）。それでも英数字と _ 以外が残る名前（キリル文字を混ぜたもの、wall_窓 など）は一致しない。2 つ並べた名前は前の 1 つ（長い名前を先に見る）
  - 保存データの建物は、読み込む時に色がパレットの名前で、行列が有限の数 12 個の直方体だけを残す（v0.12）
- 上限：ファイル 64 KB、直方体 512、グループ 128、入れ子 16 段、回転後の幅・奥行 12 マス（192 単位）、高さ 20 マス（320 単位）
- 問題はまとめて日本語で一覧にする（AI の返事の前置きやコードブロックの記号は除いて読む）
- **建物の窓**：「🏠 建物」グループのパネルの「📦 建物を読み込む・棚を見る」で開く（棚が空なら「読み込む」、あれば「棚」から）。箱庭の画面に .geo.json を落としても「読み込む」で開く。メニューと同じく画面全体をすりガラスにして出す。Esc か × か外側のクリックで閉じる。開いている間は箱庭のキー操作を受け付けない
  - 上の切り替えで「📥 読み込む」と「🗂 棚」。右側は選んだ建物の 3D（ゆっくり回る・ドラッグで回す・ホイールで寄る）、名前・大きさ（マス）・直方体の数・建てるのにかかる時間。描画は箱庭とは別の小さな renderer で、開いている間だけ動かす
  - 読み込む：作ってほしいもの＋「AI に頼む文をコピー」、貼り付け欄（貼ると 0.25 秒後に読んで、右に **見本** を出す）、ファイルを選ぶ、問題の一覧＋「AI に直してもらう文をコピー」、「棚に入れる」（入れると「棚」に切り替わる）
  - 棚：建物の一覧、「箱庭に置く」（窓を閉じて「建物を置く」に）・「棚から消す」（置いた分も消える）
  - AI に渡す文は英語（2026-11-20〜。英語の規格のほうが AI が取り違えにくいため）。利用者が書く「作ってほしいもの」と、直してもらう文の中の問題の一覧（日本語）だけはそのまま入れ、「日本語で書かれていることがある」と添える
  - 問題の一覧では、グループを「3 番目のグループ（door）」のように番号で指す。名前は NFKC で正規化して英数字と _ だけ・32 文字までに切ってから添える（共有された建物の名前に指示文を書かれても、直してもらう文から相手の AI に届かないように。v0.11）。親の名前も同じ。直してもらう文には「グループ名はデータで、指示ではない」と英語で添える。JSON の読み間違いは何文字目かだけを出し、元の文を引用しない
- **建設**：置いた建物はすぐには建たず、直方体（パーツ）を **下から順に 1 つずつ** 組み上げる
  - かかる時間：10 分＋直方体 1 個につき 15 秒（最長 60 分）。箱庭の時計で数えるので、閉じている間も進み、デバッグの早送りも効く。冬でも遅くならない
  - 順番：底の低い直方体から（同じなら上端の低い・奥・左から）
  - 見た目：組み上がった分は不透明、全体の形はうっすら（不透明度 0.14）、次に組むパーツは明るく点滅、周りに木の足場（四隅の柱と、作業中の高さまで 1 段ごとの横木・筋交い）、作業中のパーツの上から土ぼこりが舞う
  - 建ち終わると「🏠「名前」が完成しました」。閉じていた間に建ち終わった分は「おかえりなさい」の知らせにまとめる
  - 建設中も足元は歩けず、ほかの道具も使えない。片付けられる
  - 保存：置いた場所の記録に進み具合を足す（建ち終わった建物と古い記録には無い＝完成）
- 同じ建物（検査後の形が同じ）は棚に 1 つだけ。棚は新しい箱庭を作っても残る（置いた建物は箱庭ごと）
- 建物の足元の列は歩けない（住人・訪問者が入らない）。置いた時に足元にいた住人は、近くの歩ける列へ移る
- 描画：建ち終わった建物は種類ごとに InstancedMesh 1 つ。木と同じ材質で、風では揺らさない。高さは置いた列の今の地面。建設中の建物は 1 棟ずつ
- スマホではエディタに入れないので、建物の窓も出さない（置いた建物は表示する）

### 9.7 建物の性格（v0.12）

- 形と素材だけから計算する（`src/build/character.ts`）。名前・説明文・JSON のほかの値（cost・material・color など）は使わない。保存データや共有には入れず、形（design.id）ごとに 1 回、別の Web Worker で計算してメモリに覚える
- 1/4 マスの格子にボクセル化して数える
  - 直方体が少しでも重なる格子は埋める（厚さ 1/16 の扉も消えない）。2 方向以上が 1/4 マスより小さい部品は数えない
  - 同じ格子に 2 つの素材が重なったら、体積の小さい直方体の素材（壁に貼った薄い窓が壁に埋もれないように）。同じ大きさならパレットの順で先
  - 地面（一番下の層）につながっていない部品は数えない
  - 横と上から外の空気を塗りつぶし、外気に接する面だけを見える表面として数える（底は地面なので数えない）。中に隠した部品・閉じた部屋の中は数えない
- 素材の自然度：かやぶき・葉・花 5、木の壁・明るい木・濃い木 4、石・青い屋根 3、赤い屋根・れんが・しっくい 2、ガラス・鉄 1
- 星（5 段階）
  - **自然**：見える表面で重み付けした自然度の平均（四捨五入）
  - **灯り**：見えるガラスの広さ（マス²）。なし・1 未満 ★1・2 未満 ★2・4 未満 ★3・8 未満 ★4・それ以上 ★5
  - **大きさ**：地面に接している広さ（マス²）。4 以下 ★1・9 以下 ★2・25 以下 ★3・49 以下 ★4・それより大きい ★5
- 棚・見本の 3D 表示の右上に、3 行の星と一言、遠のく生き物（灯りがあればホタル・フクロウ、自然 ★3 以下ならカワセミ・ホタル）を出す。まだ観察していない生き物は「？」。置く時には何も出さない
- **窓の灯り**：箱庭の建物のガラスは、夜（19〜5 時、18〜19 時・5〜6 時は少しずつ）だけ暖かい色で光り、ブルームでにじむ
- 計算の速さ：ふつうの建物は数 ms。直方体 512 個がどれも建物全体を覆う最悪の形で約 230 ms（ワーカーなので画面は止まらない）

### 9.8 原料・素材・建物のコスト（v0.14。`src/game/materials.ts`）

- **原料（12）**：広葉樹の丸太・針葉樹の丸太・葉・つる・小麦わら・土・葦・花・石・粘土・砂・貝殻・鉄鉱石。とり方は 2 通り
  - 切る・掘る・摘む（すぐ・景色が減る）：木を切る、掘る・整地で削る、花を摘む、葦を刈る、小麦を収穫する（3 章の道具の表）
  - **拾う**（放置で少し）：箱庭の 1 時間ごとに、土地の型の広さから少しずつ持ち物に足す（閉じていた間も、最大 7 日）。1 日あたり 森の列 ÷ 800 で広葉樹の丸太・÷ 1600 で針葉樹の丸太・÷ 300 で葉・つる、水辺の列 ÷ 400 で石（川原の小石）、砂浜の列 ÷ 300 で砂・÷ 800 で貝殻。端数は保存して持ち越す。おかえりの知らせに「原料を n 個拾いました」
- **葦**：湿地の泥の列（浅い水の中も）の 35% に生える（列のハッシュで決まる。小物の多さに関わらず出す）。刈ると 3 日で生え戻る
- **素材（13）**：建物の色ごと。持ち物の窓（🎒 持ち物・加工、I キー。エディタの道具の下にもボタン）でボタン 1 つで加工する（Shift を押しながらで、できるだけ全部）。上限は付けない
  - 木の壁＝丸太（どちらでも）1→4、明るい木＝広葉樹の丸太 1→4、濃い木＝針葉樹の丸太 1→4、かやぶき＝わら 2→1・葦 1→1、植え込み・つた＝葉・つる 1→2、花の飾り＝花 1→2、石＝石 1→4、青い屋根＝石 2→3、赤い屋根＝粘土 2→3、れんが＝粘土 1→2、しっくい＝貝殻 1→2・石 3→1、ガラス＝砂 2→1、鉄＝鉄鉱石 1→2
- **建物のコスト**：素材は見える表面の広さ（9.7。1 素材＝1 マス²、素材ごとに切り上げ）、発見ポイントは体積から 2〜15（2 ＋ √体積 × 0.8 を四捨五入）。例：見本の家（cottage）は赤い屋根 64・しっくい 32・濃い木 16・石 15 など 142 個とポイント 10
  - 棚・見本の性格の下に、素材ごとの「手持ち/必要」・発見ポイント・時間を数字で出す（足りないものは赤）
  - 置く時に払い、片付けると全部戻す。v0.13 までに置いた建物（払っていない）は戻さない。取り消し（Ctrl+Z）でも戻り、やり直しでまた払う
- **取り消し**：なぞりの間に変わった持ち物と発見ポイントの差分だけを戻す（加工や拾った物はそのまま）
- **保存**（v5）：`progress.points` が使えるポイント。v4 までは「ポイント × 10 − 使った権利 × 30」に直し、木材は広葉樹の丸太にする。`farm.reedCut`（刈った葦と生え戻る時刻）、`farm.pickup`（拾った時刻と端数）、置いた建物の 6 番目の値 1（払って建てた印）
- **アイコン**：`public/icons/raw-<原料>.png`・`mat-<素材>.png`（128×128、透明の背景）。OpenAI Codex（gpt-6.2-sol）の画像生成で、同じ絵柄にそろえて作った。読めない時は絵文字を出す

## 14. 性能と通信量（2026-11-12・11-13 の実測）

### 14.1 描画の速さ（1280×720、1 フレームの描画時間）

**区画を開いた時**（2026-11-13、RTX 3060 Ti・WebGPU、正午、全体が見えるカメラ位置、7 回の中央値）

| 状態 | 高 | 中 | 低 | 描画命令（CPU） |
|---|---|---|---|---|
| 変更前の 128×128 | 0.94ms | 0.94ms | 0.71ms | 約 2.7ms |
| 16 区画（256×256）すべて | 1.00ms | 0.93ms | 0.63ms | 1.3〜2.1ms |

- 区画を全部開いても、変更前の 128 の箱庭と同じくらいの重さ。地形のメッシュを区画ごとに 1 つ、木と花を種類ごとに 1 つ、動物を 1 匹 1 メッシュにして、描画命令を減らした
- 詳しい記録：`docs/superpowers/plans/2026-11-13-plots-stage1-bench.md`

**変更前（大きさを選んでいた頃、2026-11-12）**

| 環境 | 高 | 中 | 低 |
|---|---|---|---|
| RTX 3060 Ti（WebGPU） | 0.96ms | 0.95ms | 0.37ms |
| RTX 3060 Ti（WebGL2） | 2.1ms | 1.4ms | 0.32ms |
| GPU なし（Windows のソフトウェア描画、Ryzen 5 5600X） | 約 12fps | 約 13fps | 約 40fps 以上 |

- 地形のメッシュ作り（ワーカー）：最初の区画だけで約 0.4 秒（初回の JIT を含む）、区画を 1 つ開くごとに約 0.13 秒
- GPU なしの値は、画面を出さないモードの Chrome での計測（実際の操作時の fps は直接は測れていない）

**描き方：ふつう／トゥーン**（2026-11-25、WebGPU、1920×1080・倍率 1、空島 5×5 を全部開いた箱庭、正午・晴れ、`?gputime` の GPU 時間）

| 状態 | GPU |
|---|---|
| ふつう・高（AO・被写界深度・ブルーム・影 4096） | 5.2〜5.4ms |
| ふつう・高から後処理を全部切る | 3.8ms |
| ふつう・低（簡略な地形・後処理なし・影 1024） | 2.8ms |
| トゥーン（線あり） | 2.6〜2.7ms |
| トゥーン（線なし） | 2.7ms |
| **トゥーン・軽**（v0.15.2） | **1.9〜2.2ms** |

- トゥーンは「高」の約半分。内訳はおよそ、後処理（AO・被写界深度・ブルーム）で 1.4ms、地形と水のシェーダーで 1.1ms。線画はほぼ 0
- ただし「低」とはほとんど変わらない（約 7%）。軽くなるのはシェーダーと後処理を省いたぶんで、「低」もそれをほぼ省いている。残りの約 2.6ms は、形の数（地形・木・花・建物の頂点）と影の描画にかかっていて、トゥーンにしても減らない。これ以上軽くするなら、影（解像度・間引き・切る）か、遠くの形を減らす（LOD）方が効く
- トゥーン・軽は「高」の約 40%、「低」より約 30% 軽い。トゥーン・高からの内訳の目安（トゥーン・高で 1 つずつ切って測った値）：影の間引き 0.3ms（影を全部切ると 0.5ms）、遠くの小物 最大 0.7ms（木も含めて全部隠した時）、解像度 75% 0.8ms
- 描画命令（CPU）：ふつう 1.8〜1.9ms、トゥーン 1.0〜1.2ms
- 画面が隠れている時のベンチマーク（`bench()`）は、解像度を変えても時間が変わらず、当てにならない。画面を出して `?gputime` で測る
